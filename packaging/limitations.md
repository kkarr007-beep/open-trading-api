# 한계와 하지 않은 확인

## 한 일

- Linux에서 .NET SDK 10.0.403으로 빌드하고 시험 25건이 통과했습니다.
- `win-x64`와 `linux-x64` 자체 포함 게시를 했습니다. Windows 출력에 `e_sqlite3.dll`이 있습니다.
- Linux에서 브라우저로 할 일, 건 목록, 건 상세, 관리 화면을 열었고, 상세의 서가 저장이 데이터베이스에 반영되는 것을 확인했습니다.
- 담당 세션으로 관리 주소에 들어가면 403입니다. 콘솔에 남은 기록은 그 403과 그에 따른 리소스 실패뿐입니다.

## 하지 않은 일

- 이 패키지를 Windows에서 실행하지 않았습니다. `start.cmd`, 서비스 등록, 재부팅, NTFS ACL, SMB, 방화벽, 내부 CA 인증서도 실행하지 않았습니다. `service.ps1` 의 암호 입력은 Windows에서 확인하지 않았습니다.
- 다른 PC의 브라우저로 내부망 접속을 하지 않았습니다.
- 암호화된 파일을 사용자 PC의 나스카로 여는 시험은 하지 않았습니다. 프로그램이 대신할 수 없는 사람의 확인입니다.
- Linux 화면의 글꼴은 맑은 고딕이 없어 대체 글꼴입니다. Windows에서의 맑은 고딕 렌더는 확인하지 않았습니다.
- 파일 잠금 실패는 시험 대역으로 재현했습니다. Windows 공유 위반의 실제 동작을 실행하지 않았습니다.
- SHA-256 체인은 행 내용 변조를 탐지합니다. 꼬리를 지우고 기준값까지 맞추거나, 체인 전체를 다시 계산하거나, 데이터베이스를 통째로 바꾸면 탐지하지 못합니다.
- `secure_delete`, 체크포인트, VACUUM은 논리 잔여를 줄일 뿐입니다. SSD, 섀도 복사, 예전 백업의 물리 삭제를 증명하지 않습니다.
- 복구는 원장이 최신일 때만 삭제를 다시 적용합니다. 원장까지 오래된 복사본이면 그 이후의 조기 삭제를 복원할 수 없어 일반 사용을 열지 않습니다. 한 번에 덮어쓰는 복구는 없습니다.
