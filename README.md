# 감사 포털 (개인용 · Java)

감사 건, 조치요구·이행, 자료, 징계기록을 한 사람이 자기 컴퓨터에서 관리하는 프로그램입니다.
서버판(C# / ASP.NET Core)을 Java로 옮기고 1인용으로 바꾼 것입니다.
1.4.0판부터 **업무 일정**(예전 '업무·일정 관리 v2')과 **사규**(예전 '사규 관리 시스템 v4')를 같은 창의 메뉴로 함께 씁니다.
1.5.0판에서 이름을 **감사 포털**로 바꾸었습니다.
1.6.0판에서 메뉴를 화면 위쪽(업무 일정 · 감사기록 · 사규 · 프로그램)으로 옮기고, 내용을 적는 곳마다 워드처럼 쓰는 편집기(글꼴·크기·색·형광·정렬·목록·표·표 안의 표·그림)를 넣었습니다. 등록한 자료는 '삭제' 단추로 지웁니다. 기록 폴더(`사용자 폴더\감사기록`)와 설치 위치는 그대로입니다.

사규 읽기 화면의 '징계 등재'를 누르면 그 조문이 관련규정 칸에 채워진 징계기록 등재 화면이 열립니다.

### 예전 HTML 프로그램의 데이터 옮기기

**백업 옮겨 오기** 화면(왼쪽 메뉴 '프로그램')에 예전 백업 JSON 파일을 여러 개 한꺼번에 넣으면, 파일마다 업무 일정용인지 사규용인지 가려서 넣습니다.
'전부 바꾸기' 전에는 지금 데이터를 백업 폴더에 JSON으로 남깁니다. 아래처럼 각 설정 화면에서 하나씩 넣어도 됩니다.

예전 두 프로그램은 데이터를 브라우저 안에 두었습니다. 각 프로그램에서 JSON으로 내보낸 파일을
**업무 설정 → 예전 프로그램에서 옮겨 오기**, **사규 설정 → 예전 프로그램에서 옮겨 오기**에 넣습니다.
진행 기록·체크리스트·정기 이행 표시·판·메모·북마크까지 옮겨지고, 이 프로그램에 아직 화면이 없는 항목
(사규의 위험도 매트릭스·위반 사례·시정조치·감사 이력·테마 컬렉션 등)도 버리지 않고 보관합니다.
같은 화면의 'JSON 내려받기'로 받은 파일은 예전 HTML 프로그램에서도 그대로 열립니다.

- 이 컴퓨터에서만 열립니다(`127.0.0.1:47321`). 다른 컴퓨터에서는 접속되지 않고, 로그인이 없습니다.
- 실행 중 인터넷을 부르지 않습니다. 글꼴과 스크립트는 프로그램 안의 것만 씁니다.
- 데이터는 SQLite 파일 하나, 자료 원문은 `files` 폴더에 둡니다.

## 설치해서 쓰기 (Windows)

`AuditRecord-Setup.exe`를 실행하면 바탕화면과 시작 메뉴에 **감사 포털** 아이콘이 생깁니다. 받는 방법은 [download/README.md](download/README.md)에 있습니다.

- 관리자 권한이 필요 없고, Java를 따로 설치하지 않아도 됩니다(실행 환경과 화면 엔진을 함께 넣었습니다).
- 아이콘을 누르면 **프로그램 자체 창**이 뜹니다. Edge나 Chrome을 쓰지 않습니다. 창을 닫으면 프로그램도 끝납니다.
- 이미 켜져 있을 때 아이콘을 또 누르면 떠 있는 창이 앞으로 나옵니다.
- 창 크기·위치·글자 크기를 기억합니다. F5 새로 고침, Alt+←/→ 앞뒤 화면, Ctrl +/- 글자 크기, Ctrl+K 전체 찾기.
- 창에 파일을 끌어다 놓으면 수집함으로 들어가고, 건 상세 화면에 놓으면 그 건에 붙습니다.
- 내려받기는 저장할 곳을 묻는 창이 뜨고, 인쇄용 화면의 '인쇄'는 프린터 창을 띄웁니다. PDF는 이 컴퓨터의 프로그램으로 엽니다.
- 프로그램은 `%LOCALAPPDATA%\Programs\AuditRecordLocal`에, 기록과 자료는 `사용자 폴더\감사기록`에 둡니다.
  제거해도 기록과 자료는 남습니다.

창은 JavaFX WebView(프로그램 안에 넣은 화면 엔진)로 그립니다. 화면 엔진을 쓸 수 없는 환경에서는
Edge·Chrome의 앱 창, 그것도 없으면 기본 브라우저 순으로 열립니다.

### 고칠 때는 작은 패치로

프로그램은 우리 코드가 든 `audit-record.jar`(약 0.3MB) 하나와 라이브러리(`lib`), 화면 엔진(`fx`), 실행 환경(`jre`)으로 나뉘어 설치됩니다.
고친 판은 `AuditRecord-Patch-<판>.exe`(또는 같은 이름의 zip 안의 `apply-patch.cmd`)로 그 jar 하나만 바꿉니다. 기록과 자료는 건드리지 않습니다.
패치는 1.3.0판 이상이 설치된 곳에만 적용됩니다. 1.4.0·1.5.0판은 라이브러리가 1.3.0판과 같아 패치로 바꿀 수 있습니다. 1.5.0판 패치(exe)는 바로가기와 제거 프로그램 이름도 '감사 포털'로 바꿉니다. 라이브러리나 실행 환경이 바뀐 판은 설치 파일로 다시 설치합니다.

설치 파일과 패치는 Linux나 macOS에서 만듭니다(JDK 21, Maven, nsis, pip, curl, zip 필요).

```bash
./packaging/build-installer.sh
```

## 설치하지 않고 실행

JDK 21 이상과 Maven이 필요합니다. `./run.sh`가 빌드하고 화면 엔진을 받아 자체 창으로 띄웁니다.

```bash
./run.sh
```

화면 엔진 없이 띄우면 Edge·Chrome 창이나 브라우저로 열립니다.

```bash
mvn -DskipTests package
```

```bash
java -jar target/audit-record.jar
```

`target/lib` 폴더가 jar 옆에 있어야 합니다.

실행한 위치에 `var` 폴더가 생깁니다. 설치판에서는 이 폴더가 `사용자 폴더\감사기록`입니다.

```text
var\
  data\    데이터 파일 (audit.db)
  files\   자료 원문 — 받은 그대로. 암호화된 문서는 암호화된 채로
  inbox\   수집함 — 여기에 넣은 문서는 자동으로 가져갑니다
  backup\  백업
```

다른 위치를 쓰려면 `--audit.home=D:\감사기록데이터`, 포트를 바꾸려면 `--server.port=50000`,
전용 창 대신 기본 브라우저로 열려면 `--audit.window=browser`, 아무것도 띄우지 않으려면 `--audit.window=none`을 붙입니다.

할 일 · 수집함 · 건 목록 · 건 상세 · 자료 · 징계기록 · 전체 찾기 · 관리 · 설정

왼쪽에 메뉴와 전체 찾기 칸이 있고, 화면 위에 이전 화면·목록으로 돌아가는 단추가 있습니다.
징계기록은 CSV나 엑셀(xlsx) 파일로 한꺼번에 등재할 수 있습니다(징계기록 화면의 '파일로 일괄 등재'). 전체 찾기는 건, 자료(파일명과 읽어 둔 내용), 징계기록을 한 번에 찾습니다.
백업은 하루에 한 번 자동으로 하고 최근 7개를 남깁니다(설정에서 끌 수 있음).

## 수집함

수집함 폴더나 설정에 적어 둔 폴더(예: 포털에서 내려받는 폴더)에 문서를 넣고 **지금 수집**을 누르면 가져옵니다.
창에 파일을 끌어다 놓아도 됩니다. 스스로 살펴보게 하려면 설정에서 '폴더를 15초마다 스스로 살펴보기'를 켭니다.

1. **내용 읽기**
   - 평문 파일은 프로그램이 직접 읽습니다: docx, xlsx, pptx, hwpx, hwp, doc, xls, ppt, pdf, txt, csv, html.
   - 문서보안(DRM)으로 암호화된 문서는 프로그램이 풀지 않습니다. 포털에 로그인된 이 컴퓨터의
     워드·엑셀·파워포인트·한글이 문서를 읽기 전용으로 열고, 그 프로그램이 보여 주는 글자만 받아 옵니다
     (`src/main/resources/scripts/read-document.ps1`). Windows에서만 동작합니다.
   - 로그인이 끊겨 읽지 못한 문서는 수집함에 '암호문'으로 남고, '다시 읽기'나 '지금 수집'을 누르면 다시 읽습니다.
   - 평문 docx·pptx·hwpx는 표, 그림, 문단, 굵게, 글자 크기, 정렬, 자간을 살려 화면에 옮깁니다. 엑셀과 탭으로 나뉜 글은 표로 그립니다.
     글꼴, 장평, 쪽 나눔, 그림 위치는 옮기지 않습니다. 암호화된 문서는 글자와 표(워드·엑셀)까지만 옮기고 그림은 옮기지 않습니다.
2. **항목 찾기** — 읽은 글자에서 제목, 대상, 연도, 구분, 결과 한 줄, 조치요구(지적·개선요구·권고), 회신기한,
   징계대장의 행(사번·성명·징계종류 …)을 찾습니다.
3. **등록** (설정의 '자동 등록'에 따름)
   - 감사번호(`2026-01-03`)나 건 제목이 문서에 나오면 그 건에 붙입니다. 회신 문서면 조치요구의 회신으로 기록합니다.
   - 맞는 건이 없는 결과 문서는 새 건 **초안**과 조치요구를 만듭니다.
   - 징계대장·의결서는 징계기록 **초안**으로 등재합니다.
   - 판단이 서지 않는 것은 수집함의 '확인 대기'에 남고, 제안된 값을 고쳐 단추 하나로 등록합니다.

자동으로 만드는 것은 모두 초안입니다. 결과 확정, 종결, 징계기록 확정은 사람이 합니다.
항목 찾기는 규칙 기반이라 문서 양식에 따라 틀릴 수 있습니다. 규칙은 `DocAnalyzer.java`에 모여 있습니다.

## 서버판과 달라진 것

| 항목 | 서버판 | 개인용 |
| --- | --- | --- |
| 언어 | C# / ASP.NET Core | Java 21 / Spring Boot + JavaFX 창 |
| 접속 | 내부망의 여러 사람 | 이 컴퓨터 한 대 |
| 계정·역할 | 담당·파트장·관리자, 비밀번호 | 없음 (설정의 '내 이름'이 이력에 남음) |
| 문서 내용 | 읽지 않음 | 읽어서 등록과 찾기에 씀 |
| 찾기 | 제목·대상·문서번호·파일명 | + 결과 본문, 자료 내용 |
| 원문 열기 | 내려받기 | '열기' 단추로 이 컴퓨터의 프로그램에서 바로 열기 |
| 보존 삭제 | 정책 확인 후 자동 | 기본은 수동, 설정에서 자동으로 바꿈 |

그대로 둔 것: 문서번호 자동 부여, 초안→확정→조치중→종결, 보존연한과 만료 삭제, 삭제 보류,
사유 필수 규칙, 추가만 되는 이력과 SHA-256 지문(훼손 표시), 징계기록 등재 항목과 성명 가림, CSV, 백업, 인쇄용 화면.

뺀 것: 로그인·계정 관리, 간편 설치·서비스 등록, 삭제 작업 대기열과 복구 대조, 요청 번호 중복 방지.

## 유의할 점

- 읽어 둔 문서 내용은 암호화되지 않은 글자로 `var\data\audit.db`와 백업에 들어갑니다.
  원문에 걸린 문서보안이 이 글자에는 적용되지 않습니다. 사내 보안 규정에 맞는지 확인하고,
  맞지 않으면 설정에서 '읽은 내용을 저장해 찾기에 쓰기'나 '사무용 프로그램으로 열어 읽기'를 끄세요.
- 로그인이 없으므로 이 컴퓨터의 Windows 계정을 쓰는 사람은 누구나 볼 수 있습니다.
- 이력 지문은 줄을 직접 고친 것을 드러냅니다. 전체를 다시 계산해 바꾼 경우는 알아내지 못합니다.

## 확인한 것과 하지 않은 것

- Linux에서 빌드하고 자동 시험 11건이 통과했습니다(`mvn test`).
- 설치판과 같은 구성(Java 25 실행 환경 + 화면 엔진 25)의 Linux용으로 가상 화면에서 자체 창을 띄워
  할 일, 수집함, 건 상세, 설정, 전체 찾기, 미리보기 창, 다크 화면, 창과 화면 사이의 연결을 확인했습니다.
- 예시 문서로 자동 수집, 초안 생성, 회신 기록, 징계기록 등재, 확정, 이전 판 가져오기를 확인했습니다.
- **Windows에서는 실행하지 않았습니다.** 설치 파일, 바로가기, Windows에서의 자체 창, 저장 창·인쇄·파일 끌어다 놓기,
  사무용 프로그램으로 암호화 문서를 여는 스크립트, 실제 문서보안 제품과의 동작은 확인하지 못했습니다.
- 저장 창, 인쇄, 복사, 파일 끌어다 놓기는 사람 손이 필요한 동작이라 Linux에서도 눌러 보지 못했습니다.
- 함께 넣는 실행 환경에 없는 `jdk.xml.dom` 묶음은 빌드하는 컴퓨터의 JDK 21에서 꺼내 넣습니다.
- 자체 창에는 날짜 달력이 뜨지 않을 수 있어 날짜를 `2026-12-31`, `2026.12.31`, `20261231` 꼴로 적어도 받도록 했습니다.
- 실제 감사 문서 양식으로 항목 찾기를 맞춰 보지 않았습니다. 예시 문서로만 확인했습니다.
- 이전 판 데이터 가져오기는 서버판 표 구조로 만든 예시 데이터로만 확인했습니다.
