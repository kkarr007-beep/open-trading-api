# 감사기록 (개인용 · Java)

감사 건, 조치요구·이행, 자료, 징계기록을 한 사람이 자기 컴퓨터에서 관리하는 프로그램입니다.
서버판(C# / ASP.NET Core)을 Java로 옮기고 1인용으로 바꾼 것입니다.

- 이 컴퓨터에서만 열립니다(`127.0.0.1:47321`). 다른 컴퓨터에서는 접속되지 않고, 로그인이 없습니다.
- 실행 중 인터넷을 부르지 않습니다. 글꼴과 스크립트는 프로그램 안의 것만 씁니다.
- 데이터는 SQLite 파일 하나, 자료 원문은 `files` 폴더에 둡니다.

## 설치해서 쓰기 (Windows)

`AuditRecord-Setup.exe`를 실행하면 바탕화면과 시작 메뉴에 **감사기록** 아이콘이 생깁니다.

- 관리자 권한이 필요 없고, Java를 따로 설치하지 않아도 됩니다(실행 환경을 함께 넣었습니다).
- 아이콘을 누르면 주소 줄과 탭이 없는 전용 창이 뜨고, 창을 닫으면 프로그램도 끝납니다.
  전용 창은 이 컴퓨터의 Edge(없으면 Chrome)를 창 틀만 빌려 쓰는 것입니다. 둘 다 없으면 기본 브라우저로 열립니다.
- 이미 켜져 있을 때 아이콘을 또 누르면 창만 하나 더 뜹니다.
- 프로그램은 `%LOCALAPPDATA%\Programs\AuditRecordLocal`에, 기록과 자료는 `사용자 폴더\감사기록`에 둡니다.
  제거해도 기록과 자료는 남습니다.

설치 파일은 Linux나 macOS에서 만듭니다(JDK 17+, Maven, nsis, pip 필요).

```bash
./packaging/build-installer.sh
```

## 설치하지 않고 실행

JDK 17 이상과 Maven이 필요합니다.

```bash
mvn -DskipTests package
```

```bash
java -jar target/audit-record.jar
```

실행한 위치에 `var` 폴더가 생깁니다. 설치판에서는 이 폴더가 `사용자 폴더\감사기록`입니다.

```text
var\
  data\    데이터 파일 (audit.db)
  files\   자료 원문 — 받은 그대로. 암호화된 문서는 암호화된 채로
  inbox\   수집함 — 여기에 넣은 문서는 자동으로 가져갑니다
  backup\  백업
```

다른 위치를 쓰려면 `--audit.home=D:\감사기록데이터`, 포트를 바꾸려면 `--server.port=50000`,
전용 창 대신 기본 브라우저로 열려면 `--audit.window=browser`, 아무것도 띄우지 않으려면 `--audit.window=none`을 붙입니다.

## 자동 수집 (새 기능)

수집함 폴더나 설정에 적어 둔 폴더(예: 포털에서 내려받는 폴더)에 문서가 생기면 15초 안에 가져옵니다.

1. **내용 읽기**
   - 평문 파일은 프로그램이 직접 읽습니다: docx, xlsx, pptx, hwpx, hwp, doc, xls, ppt, pdf, txt, csv, html.
   - 문서보안(DRM)으로 암호화된 문서는 프로그램이 풀지 않습니다. 포털에 로그인된 이 컴퓨터의
     워드·엑셀·파워포인트·한글이 문서를 읽기 전용으로 열고, 그 프로그램이 보여 주는 글자만 받아 옵니다
     (`src/main/resources/scripts/read-document.ps1`). Windows에서만 동작합니다.
   - 로그인이 끊겨 읽지 못한 문서는 수집함에 '암호문'으로 남고 10분마다 다시 읽습니다.
2. **항목 찾기** — 읽은 글자에서 제목, 대상, 연도, 구분, 결과 한 줄, 조치요구(지적·개선요구·권고), 회신기한,
   징계대장의 행(사번·성명·징계종류 …)을 찾습니다.
3. **등록** (설정의 '자동 등록'에 따름)
   - 감사번호(`2026-01-03`)나 건 제목이 문서에 나오면 그 건에 붙입니다. 회신 문서면 조치요구의 회신으로 기록합니다.
   - 맞는 건이 없는 결과 문서는 새 건 **초안**과 조치요구를 만듭니다.
   - 징계대장·의결서는 징계기록 **초안**으로 등재합니다.
   - 판단이 서지 않는 것은 수집함의 '확인 대기'에 남고, 제안된 값을 고쳐 단추 하나로 등록합니다.

자동으로 만드는 것은 모두 초안입니다. 결과 확정, 종결, 징계기록 확정은 사람이 합니다.
항목 찾기는 규칙 기반이라 문서 양식에 따라 틀릴 수 있습니다. 규칙은 `DocAnalyzer.java`에 모여 있습니다.

## 서버판과 달라진 것

| 항목 | 서버판 | 개인용 |
| --- | --- | --- |
| 언어 | C# / ASP.NET Core | Java 17 / Spring Boot |
| 접속 | 내부망의 여러 사람 | 이 컴퓨터 한 대 |
| 계정·역할 | 담당·파트장·관리자, 비밀번호 | 없음 (설정의 '내 이름'이 이력에 남음) |
| 문서 내용 | 읽지 않음 | 읽어서 등록과 찾기에 씀 |
| 찾기 | 제목·대상·문서번호·파일명 | + 결과 본문, 자료 내용 |
| 원문 열기 | 내려받기 | '열기' 단추로 이 컴퓨터의 프로그램에서 바로 열기 |
| 보존 삭제 | 정책 확인 후 자동 | 기본은 수동, 설정에서 자동으로 바꿈 |

그대로 둔 것: 문서번호 자동 부여, 초안→확정→조치중→종결, 보존연한과 만료 삭제, 삭제 보류,
사유 필수 규칙, 추가만 되는 이력과 SHA-256 지문(훼손 표시), 징계기록 등재 항목과 성명 가림, CSV, 백업, 인쇄용 화면.

뺀 것: 로그인·계정 관리, 간편 설치·서비스 등록, 삭제 작업 대기열과 복구 대조, 요청 번호 중복 방지.

서버판 데이터는 관리 화면의 '이전 판 데이터 가져오기'로 옮깁니다(비어 있을 때 한 번).

## 유의할 점

- 읽어 둔 문서 내용은 암호화되지 않은 글자로 `var\data\audit.db`와 백업에 들어갑니다.
  원문에 걸린 문서보안이 이 글자에는 적용되지 않습니다. 사내 보안 규정에 맞는지 확인하고,
  맞지 않으면 설정에서 '읽은 내용을 저장해 찾기에 쓰기'나 '사무용 프로그램으로 열어 읽기'를 끄세요.
- 로그인이 없으므로 이 컴퓨터의 Windows 계정을 쓰는 사람은 누구나 볼 수 있습니다.
- 이력 지문은 줄을 직접 고친 것을 드러냅니다. 전체를 다시 계산해 바꾼 경우는 알아내지 못합니다.

## 확인한 것과 하지 않은 것

- Linux에서 빌드하고 자동 시험 9건이 통과했습니다(`mvn test`). 함께 넣는 것과 같은 판(Java 25)의 Linux용 실행 환경으로도 띄워 보았습니다.
- 창이 닫히면 프로그램이 끝나는 것과 중복 실행 방지는 Linux에서 흉내 낸 창 프로그램으로 확인했습니다.
- Linux에서 프로그램을 띄워 예시 문서로 자동 수집, 초안 생성, 회신 기록, 징계기록 등재, 확정, 내용 미리보기를 확인했습니다.
- **Windows에서는 실행하지 않았습니다.** 설치 파일, 전용 창, `run.cmd`, 사무용 프로그램으로 암호화 문서를 여는 스크립트,
  실제 문서보안 제품과의 동작은 확인하지 못했습니다. 암호화 문서 판별은 파일 첫머리가 형식과 다른지로 합니다.
- 실제 감사 문서 양식으로 항목 찾기를 맞춰 보지 않았습니다. 예시 문서로만 확인했습니다.
- 이전 판 데이터 가져오기는 서버판 표 구조로 만든 예시 데이터로만 확인했습니다. 실제 서버판 데이터로는 실행해 보지 않았습니다.
