### R1. SHA-256 앞줄 체인 · 이력 무결성 표시

**원문:** USER_SPEC §5 이력 — “각 이력 줄은 앞줄의 지문(SHA-256)을 가진다. 누군가 데이터 파일을 직접 고치면 화면 상단에 이력 훼손으로 표시. 외부 서비스 없음.” 끝나는 기준 6.

**심각도:** High (탐지 목적에는 유효할 수 있으나, 관리자·디스크 전면 통제자 대항 **방어가 아님**. 과신 시 Critical급 오판)

#### 발생조건

1. 앱이 연 뒤 SQLite에서 이력 행의 필드·순서를 직접 UPDATE/DELETE/INSERT.
2. 꼬리 N행만 삭제(남은 prefix는 체인상 유효)하거나 마지막 행 필드만 변조.
3. head/lastSequence 메타까지 맞춰 바꾸거나, 체인 전체 재계산 후 DB(+checkpoint)를 동시 맞춤.
4. DB·백업·별도 checkpoint를 같은 공격자가 모두 소유.

#### 최소해결책 (기능 팽창 없이 · 미승인 제안)

1. **해시 입력에 포함할 필드**  
   `H_i = SHA256( canonical(row_i) || H_{i-1} )`.  
   최소: `sequence`, `occurredAt`, `action`, `targetKey`, `summary`, `actorUserId`, `prevHash`.  
   **자기 행 의미 필드가 해시에 들어가야** 마지막 행 필드 변조도 재계산 없이 탐지. `prevHash`만으로는 약함.
2. **canonical 규칙 고정**  
   임의 구분자 연결은 모호하다. **버전 고정**된 (a) length-prefix 필드열 또는 (b) 키 정렬·타입 고정 canonical JSON. UTF-8, 날짜 ISO-8601+명시적 오프셋(Asia/Seoul). 변경은 마이그레이션+전체 재검증만.
3. **sequence**  
   PRIMARY/UNIQUE, 앱 INSERT만. **contiguous를 훼손 신호로 쓰려면** 롤백 시 채번 소모/재사용 정책을 먼저 확정(미정 시 “갭=훼손” 단정 금지).
4. **검증·훼손 시 동결(미승인 권고)**  
   로그인·이력 로드 시 재계산, 불일치 시 상단 배너. 이력 append만 막고 일반 업무 쓰기를 허용하면 “모든 변경은 이력에 동시 기록”과 충돌한다. 권고: 훼손 플래그 시 **업무 상태변경 API도 동결**, 읽기만 허용.
5. **append-only는 화면만이 아님**  
   서버에서 이력 UPDATE/DELETE 경로 없음. DB 파일을 직접 연 공격자 앞에서는 **탐지**이지 방지 아님.
6. **삭제·본문 비우기와 체인**  
   업무 테이블 본문 NULL·파일 삭제·(성공 후) 경로 비움은 **기존 이력 행을 고치지 않음**. 새 이력 summary에는 표시이름·종류·건 ID 정도만. **본문·경로·비번을 hash/이력에 넣지 말 것.**
7. **보장 경계 (UI/운영 문서 명시)**  
   - 탐지 가능(전형): 행 필드 변조(자기 필드 포함 시), 중간 삭제 후 재연결 실패.  
   - **순수 체인 + 꼬리 삭제:** 마지막 N행만 지우면 남은 prefix는 유효. 독립 expected tail/count(또는 DB 밖 checkpoint)가 없으면 **재계산 없이도 탐지 불가**.  
   - **조건부:** 동일 DB head/lastSequence가 그대로면 길이·head 불일치로 탐지 가능. 공격자가 head도 맞추면 우회.  
   - 전체 재계산+head(+외부 checkpoint) 동시 변조는 앱만으로 미탐지. 같은 DB head·코드 비밀 ≠ 관리자 대항 방어.
8. **선택 운영 최소책**  
   `headHash+lastSequence+takenAt`을 DB와 ACL이 다른 위치/인쇄로 사람이 보관. **탐지력 향상**이지 보증 아님. 원설계 필수 아님 → 권고·별도 승인.

### R2. SQLite·디스크에 삭제 본문·파일 잔존

**원문:** §6 만료 시 본문 비움·파일 삭제(휴지통 없음). 메타·이력 잔존.

**심각도:** High (논리 삭제 ≠ 물리 완전파기. “지웠다”를 복구 불가로 오해하면 규정 위반 소지)

#### 발생조건

- UPDATE로 본문 NULL 후에도 DB 자유 페이지·WAL·rollback journal·임시 파일에 이전 값이 남음.
- `files\`에서 삭제 후에도 VSS·백업·SSD 블록에 잔존.
- 전문 검색 인덱스·로그에 본문을 남긴 경우(설계 금지 위반).

#### 최소해결책

1. **용어 분리**  
   - **논리 삭제:** 본문 NULL·파일 unlink·이력 append. **저장위치 비움·삭제일·`자료삭제됨`은 파일 삭제(또는 이미없음) 확인 후에만**(R3).  
   - **물리 잔존 완화:** 완전 파기 증명 불가.
2. **앱이 하지 말 것** — 본문 FTS/검색테이블/로그 복사 금지. 예외에 본문·경로·비번 금지.
3. **SQLite 정비 (유지보수 창)**  
   - `PRAGMA secure_delete=ON` 검토. 한계: WAL·이전 페이지·FS 복사본.  
   - 순서: 연결 정리 → 필요 시 `VACUUM` → **성공 후에도 WAL이 다시 남을 수 있으므로** `wal_checkpoint(TRUNCATE)` → busy=0·결과 확인.  
   - VACUUM 여유는 환경에 따라 **최악 총 여유 약 DB 2배**까지 보수적으로(≈1배 단정 금지).  
   - 정비 중 쓰기 배타 권고.
4. **파일** — `File.Delete`는 휴지통으로 보내지 않고 삭제하지만 **물리 파기 아님**. FileOptions를 휴지통 우회 API처럼 표현하지 말 것. BitLocker≠건단위 파기 증명.
5. **백업과의 관계** → R4.

### R3. 보존연한 · 확정/취소 · 삭제 보류 · 삭제 경합

**원문:** 기산일=결과확정일. 연한 없으면 확정 불가. 삭제 보류 중이면 만료해도 삭제 안 함. 확정 취소 후 파일이 이미 없으면 복구 안 함·이력 기록. 서버 off면 기동 시 처리.

**심각도:** High (기산·경합 오류 시 조기삭제 또는 무기한 잔존)

#### 발생조건

- 기산: **최초 확정일 유지 vs 재확정일로 연장**(반복 취소로 연한 무기한 갱신 위험). 원문만으로 결정 불가.
- 경로 NULL·`자료삭제됨`/삭제일을 파일 삭제 **전에** 확정 → 완료 오표시·재시도 키 소실.
- DB 단일 tx commit 이후 파일 삭제와 **뒤늦은 보류**는 tx만으로 해결 안 됨.
- 윤년·타임존·확정일+N년 경계 모호.

#### 최소해결책 (미승인 제안)

1. **만료 판정 (총괄 문서화 기본, 법률 수치 발명 금지)**  
   - `retentionYears`는 건 입력. `DateOnly`·Asia/Seoul. 달력년 가산·2/29→그 달 말일 등을 운영 기본으로 문서화.  
   - 자동삭제는 **정책 승인 전 기본 보류**. 이력에 모든 확정/취소일 보존. **현재유효 확정일**과 **기산일** 개념 구분.
2. **확정 취소·기산 — 대표 확인(U1)**  
   - 갈림: **최초 확정일 유지(기산 고정)** vs **재확정일로 기산 연장**. 후자는 반복 취소·재확정으로 연한 갱신 위험.  
   - “취소 중 배제+재확정 새 기산”을 저장만 다르게 한 두 안은 **서로 다른 업무정책이 아님**.  
   - 이미 삭제된 파일은 복구 안 함(원문).
3. **파일 삭제 최소 프로토콜 (장기 tx 없음)**  
   - 건별 **lock + state machine**을 보류/확정취소/연한변경 API와 worker가 공유. 본문을 비우는 DB 작업도 같은 보호구간에서 보류·기산을 확인하고 이력과 함께 커밋한다. 삭제 직전 재확인부터 실제 파일 삭제까지 lock을 유지하여 그 사이 보류가 끼지 않게 한다.  
   - pending 내부 작업에 **검증된 StorageKey만** 보존(audit 이력에 경로 복사 금지).  
   - 파일 삭제(또는 이미없음) **성공 확인 후**에만 삭제일·완료상태·저장위치 비움. 실패 시 pending 명시, **성공 거짓 표시 금지**. 완료 후 pending 키 제거.  
   - 외부 파일 삭제 **직전** 상태 재검증(보류면 중단). irreversible 시작 이후 보류는 **소급 복구 불가**를 UI/이력에 표시.
4. **멱등** — 이미없음 → 성공 후 최종 메타. 이미 완료 → 스킵.
5. **확정 후·연한 전 관리자 삭제** — 사유 필수, 이력에 앞뒤만.
6. **종결** ≠ 삭제. 연한까지 파일·본문 유지.

### R4. 백업 일관성 · 삭제본문 재유입

**원문:** 관리자가 data + files를 내부 디스크 경로로 복사. 인터넷 백업 없음.

**심각도:** High (잘못된 복사=복구 불가 백업. 무기한 백업=보존연한 우회)

#### 발생조건

- 실행 중 DB 단순 복사 → WAL 미포함·깨진 스냅샷.
- 백업 도중 업로드/삭제가 끼어 DB↔files 불일치. “최대한 가깝게”는 보장 아님.
- 만료 후에도 백업에 본문·암호문 영구 보관.
- 복원 시 이후 보류·기삭제 명세를 잊거나, 지운 원문 자동 부활.

#### 최소해결책 (미승인 제안)

1. **backup gate**  
   - DB snapshot + 필요 files 복사 **전체**에 걸쳐 변경 API·업로드·삭제 worker와 **동일 gate**로 멈춘 뒤 정합 스냅샷 확정. gate는 성공·실패 모두 `finally`에서 해제하며, 실패 백업은 미완료로 격리한다.  
   - DB: Backup API 또는 잠금+`wal_checkpoint(TRUNCATE)` 후 복사. live 단순 복사+WAL 누락 금지.  
   - 실패·부분본에 **완료** 명칭 금지.
2. **백업 수명(U2)**  
   - 운영 복구용. 연한 대체 저장소 금지. **화면 입력 UI 추가 요구 없음** — 운영 고정설정·폐기 절차로 최소화.
3. **복원**  
   - 낡은 백업 hold/state만 보면 **이후** 보류·기삭제를 잊는다. 복원 전 **최신 삭제·보류 메타 명세** 확보·재적용. 없으면 서비스 재개 전 **관리자 확인**.  
   - 복원본 hold로 자동파기하거나 이미 지운 원문 **자동 부활·재노출 금지**. 오프라인 검증 후 오픈.
4. **내용·부가물**  
   - 암호문 바이트만. 원문 복사 **외** 추가 파일/해시 checkpoint는 **권고·별도 승인**(원설계 필수 아님).

#### 구체 검증기준

| # | 기준 | 유형 |
|---|------|------|
| V4.1 | live File.Copy(db)만 없음. Backup API 또는 잠금+checkpoint | 로컬 논리 |
| V4.2 | backup gate가 업로드·삭제·상태변경과 공유. 예외 후 gate 해제·업무 복구 확인, 실패본에 완료 라벨 없음 | 로컬 논리 |
| V4.3 | 복원: 최신 삭제/보류 명세 재적용 또는 관리자 확인. 자동 원문 부활 없음 | 로컬·수동 |

### R5. 파일 경로 · traversal · NASCA 위치 분리

**원문:** files\ 아래 원문. 화면에는 위치만. 프로그램은 내용 안 읽음. 끝나는 기준 7.

**심각도:** Critical에 가까울 수 있음(경로 조작으로 서버 임의파일 삭제/유출). 최소책 준수 시 완화 여지.

#### 발생조건

- 클라이언트가 상대/`..`/절대/UNC/드라이브/ADS/junction을 경로로 넘김.
- DB StorageKey 변조 후 삭제 API가 그 경로를 unlink.
- 표시용 공유 경로와 서버 삭제 키를 동일 컬럼으로 섞음.

#### 최소해결책 (미승인 제안)

1. **서버 생성 키만**  
   - API는 **첨부/건 ID만**. 클라이언트 StorageKey·경로 지정 불가.  
   - 서버가 `caseId`·`guid`·안전 확장자를 **세그먼트별** 엄격 검증 후 결합. “키 문자열 slash 전면 거부”와 `files/{caseId}/{guid}` 예시가 충돌하지 않게.
2. **root 검증**  
   - `Path.GetFullPath`는 reparse/junction **실제 타깃을 해석하지 못함**. root-prefix는 **separator 경계** + Windows `OrdinalIgnoreCase`.  
   - 구성요소 재분석점 거부 시도 + 업로드로 reparse를 만들기 어렵게 ACL. **“폴더 ACL로 재분석점 생성만 금지” 단정 금지.**  
   - 잠금·검증 후 열기/삭제까지 TOCTOU 잔존·관리자 전면 통제 한계 명시.
3. **표시 위치 vs 삭제 키 분리** — 표시 문자열로 File.Delete 금지.
4. **읽기 금지** — ReadAll/미리보기/추출/썸네일 없음. 백업은 바이트 복사.
5. **NASCA** — 사람 시험만(원문 §3).

| # | 기준 | 유형 |
|---|------|------|

| V5.2 | DB에 악성 상대키를 심은 뒤 삭제 API → 거부, root 밖 unlink 0건 | 로컬 자동 |

### R6. 계정 · 권한 · CSRF · TLS · ACL · DataProtection

**원문:** 로컬 계정. 포털/SSO 비연동. 역할 표 §4. 관리자만 계정·백업·보류·연한 전 삭제.

**심각도:** Critical(권한·고정비번·IDOR) ~ High(CSRF·세션) ~ Medium(현장 ACL)

#### 발생조건

- 평문·자체 SHA만·고정 초기비번.
- UI만 숨기고 API는 담당도 확정 가능.
- 상태변경 CSRF 없음. GET으로 삭제.
- 내부 HTTP만으로 로그인 비밀 스니핑.
- DB·backup Everyone 읽기. DataProtection 키 휘발 또는 일반 백업에 동봉 노출.
- 로그에 비번·본문.

#### 최소해결책 (미승인 제안)

1. **비밀번호** — `PasswordHasher`. 평문·고정비번 금지. 최초 admin 강제 변경. 잠금 횟수·대기는 **총괄이 코드 상수·운영문서에 고정**(대표 질문 아님).
2. **초기화** — 임시 비밀 + 세션 전부 폐기 + 강제 변경. 사용중지 즉시 차단.
3. **권한** — 모든 상태변경 서버 역할 강제. 담당은 확정/종결/보류/계정/백업/연한전삭제 거부. 이력 수정/삭제 전 역할 404/405.
4. **CSRF·쿠키** — 상태변경 POST 계열+antiforgery. GET 읽기만. `HttpOnly`, `SameSite`, HTTPS 시 `Secure`.
5. **TLS·네트워크** — 내부망이라도 **운영 전 기본 게이트: HTTPS + 사설 CA 신뢰**. HTTP는 **명시적 위험수용 문서 없이는 운영 보류**. 방화벽·외부 출구 차단.
6. **NTFS ACL** — `data\`·`backup\`는 서비스(+행정 admin)만. `files\` 읽기 공유와 DB ACL 분리. Everyone Full 금지.
7. **DataProtection** — 키 링은 SQLite data와 **분리된 ACL 경로** + Windows DPAPI 등 at-rest 권고. **일반 백업에 키 무조건 동봉·노출 금지**. 클라우드 키스토어 금지.
8. **로그** — 비번·토큰·본문·경로 전문 금지.
9. **외부 호출** — CDN·폰트·telemetry·update 0.

| # | 기준 | 유형 |

| V6.1 | PasswordHasher, 평문 컬럼 없음 | 로컬 논리 |
| V6.2 | 담당 토큰으로 확정/종결/보류/계정 → 403 | 로컬 자동 |
| V6.3 | 관리자 외 연한전삭제 → 403. 사유 빈 값 → 4xx | 로컬 자동 |
| V6.4 | 이력 UPDATE/DELETE 엔드포인트 없음 | 로컬 논리 |
| V6.5 | 상태변경 CSRF 없으면 400 | 로컬 자동 |

## 5. 잔여위험 요약 (과신 방지)

1. **해시 체인**은 탐지용. 꼬리 삭제만으로는 prefix 유효(expected tail/head 없으면 미탐지). head 동시 변경·전면 재계산은 우회. 관리자 대항 방지 아님.  
2. **논리 삭제** 후 WAL·자유페이지·백업·VSS·SSD 잔존 가능. BitLocker≠건단위 파기. File.Delete≠물리파기.  
3. **파일·DB**는 장기 tx 없음. pending StorageKey→성공 후 완료 메타. 보류는 삭제 직전 재검증·소급복구 불가.  
4. **NASCA·NTFS·reparse**는 현장. GetFullPath만으로 junction 해석 보장 없음. HTTPS는 운영 전 기본 게이트.  
5. **백업**은 공유 gate로 정합 스냅샷. 낡은 복원+이후 보류/기삭제 망각·원문 자동부활 금지. 무기한 백업=연한 우회.  
6. 본 문서는 **설계 검토·미승인 제안**. 구현 후 코드·테스트·현장으로 재대조.
