## 1. 공통 골격·시각·개인정보 경계

### 1.1 한줄 헤더

데스크톱 48px 한 줄: `감사기록 | 할 일 | 건 목록 | [관리] | 내부망 | 가상사용자 · 담당 | 비밀번호 | 나가기`.
건 상세는 건 목록의 하위문맥이며 새 전역탭을 만들지 않는다. 관리 탭은 관리자만, 현재화면 링크에 `aria-current=page` 하나. 짧은 라벨 **내부망**은 배포경계 표기이지 안전보증 마크가 아니다. 옆면 아이콘 레일·차트·카드·그래프·별도 대시보드 없음. 로그인 전에는 앱 이름+내부망만 표시한다.

200%/좁은 창에서는 헤더 자체 가로스크롤 가능하되 포커스 항목이 가려지지 않게 한다. 탭을 의미 없는 아이콘으로 바꾸지 않고 본문은 단일열 재배치한다. 모바일 하단탭은 이번 원문 범위에 없어 자동 도입하지 않는다. 헤더 아래 오류/훼손/정비 메시지는 별도 영역이며 한줄헤더를 깨는 nav 요소가 아니다.

- Windows 설치 **맑은 고딕** 시스템폰트 `Malgun Gothic`만. 웹폰트·CDN·외부 CSS/JS·telemetry·분석픽셀·외부 아이콘요청0. 폰트 누락은 운영환경 점검사항, 인터넷 대체폰트 내려받지 않는다.
- 기본본문14px/줄간격1.5, 제목18~22px, 표14px, 메타12~13px 추천. 일반 텍스트 대비4.5:1, 큰글자/비텍스트·포커스3:1 이상 목표. 숫자/날짜는 정렬폭 일정하게, 지워진 상태도 읽을 수 있는 대비.
- 표 기본 행높이36px(허용32~40), 필터/주요버튼 최소36px; 터치 환경은44px 이상. 글자/확대 때문에 높이가 늘어날 수 있게 min-height 사용, 고정높이로 자르지 않는다. 고밀도24px 기본 미채택.
- 공통 footer는 `시각 KST`와 필요 상태만. 이름·제목이 브라우저 제목/주소에 남지 않도록 document.title은 “건 상세 · 감사기록”처럼 일반명만.

### 1.2 검색·필터·돌아가기

- 검색은 제목/대상/문서번호/철번호만. 본문/파일내용검색 금지. 입력 label “제목·대상·문서번호·철번호”, 검색 버튼/Enter로 POST. 타이핑마다 원격/외부 호출 없음.
- raw 검색어·필터 값·건제목은 URL/querystring·fragment·history.state·브라우저 저장소(local/sessionStorage)·로그에 넣지 않는다. 목록 주소는 일반 route. CSRF 토큰과 POST body는 로깅하지 않는다. 입력 autocomplete=off·spellcheck=off 추천(브라우저가 완전 준수한다는 보장 없음).
- 기본 추천은 현재 탭 JS 메모리에 필터/검색/정렬/스크롤/복귀링크ID 저장. 일반 Razor 페이지 이동에 필요한 복귀는 세션별 서버 메모리에 단기 view token(무작위, 사용자결합, 30분 이하)을 두고 현재 폼 hidden 값/복귀 POST로만 참조하며, GET URL이나 DB에 저장하지 않는다. token도 raw query가 아니며 인증 대체물이 아니다. 단순 GET/Back에서 token이 없으면 조건초기화가 정직한 기본이며 복원보장을 과장하지 않는다. URL은 일반 /cases 및 /cases/{불투명ID}만.
- 필터 submit 후 목록렌더→상태영역에 “검색 결과 n건” polite 공지. 활성필터는 칩과 개별 제거버튼, “모두 지우기”. raw 검색어 칩을 다른 화면/공통헤더에 복제하지 않는다.
- 상세의 “목록으로”와 브라우저 Back은 살아 있는 현재탭 메모리가 있으면 필터/정렬/스크롤/해당 건 링크 포커스를 복원. 새로고침·새탭·세션만료·서버재시작이면 raw 검색어는 복원하지 않고 “검색 조건이 초기화되었습니다”로 안내한다. 개인정보 최소화 때문에 영구 URL 공유/무조건 재로드 보존을 제공하지 않는 명시적 tradeoff다.
- 응답 `Cache-Control: no-store`, Referrer-Policy:no-referrer. 뒤로가기 캐시·자동완성·화면캡처를 완벽 차단한다고 주장하지 않는다. 외부링크/다운로드/내보내기 기능 추가 없음.

### 1.3 상태·행동 언어

| 표시 | 의미/근거 | 혼동 방지 |
|---|---|---|
| 초안 / 확정 / 조치중 / 종결 / 자료삭제됨 | S의 표시상태5개, A §5 파생 | 삭제 미완료는 새 업무상태 아님 |
| 회신 수신 | 담당이 받은 회신 입력 | 이행 완료 아님 |
| 이행 완료 | 감사파트 확인을 명시 기록(추천 상태) | 종결 자동처리 아님 |
| 종결 | 조치가 끝났다는 권한자 표시 | 연한전 파일/본문 유지 |
| 삭제 보류 | 만료라도 삭제 안함 | 만료일 연장·파일복구 아님 |
| 삭제 미완료 1건 | 본문/파일 부분실패, 내부 job | 자료삭제됨 성공색/문구 금지 |
| 자료삭제됨 | 대상 본문·파일·경로 모두 제거확인 후만 | 물리완전파기/과거종결 뜻 아님 |
| 파일 없음—확인 필요 | 등록자료 누락 | 정상삭제/등록안됨과 구별 |

문구는 글자+필요시 간단 도형으로, 색에만 의존하지 않는다. 빨강=위험/오류, 파랑=포커스/작업, 회색=삭제 사실이되 충분한 대비. 이력훼손은 노랑/빨강 배너+“이력 훼손” 텍스트, 정상확정 표시보다 우선 노출.

## 2. 할 일

### 영역과 역할

1. 제목 `할 일`, 설명 “감사파트 전체 건 기준”. **담당:** 회신기한 초과 조치요구 표만. **파트장·관리자:** 확정 대기 / 회신기한 초과 / 30일 안 삭제예정 표를 세로로 잇는다. 카드·수치 대시보드·그래프 없음.
2. 각 표에 caption+건수, 본문은 한줄 링크 중심. 원문이 담당자 자신의 건만 보이라고 정하지 않았으므로 로그인 역할로 콘텐츠 종류만 바꾸고 소유자 제한하지 않는다.
3. 확정대기 기준 추천: 최소 결과·연한이 입력된 초안. 아직 승인된 새로운 결재요청 상태가 아니며 총괄이 A §13에 기준을 기록한다.

| 표 | 컬럼 | 기본정렬 | 행 동작 |
|---|---|---|---|
| 회신기한 초과 | 건 제목, 조치순번·제목, 대상, 담당, 회신기한, 초과일수/상태 | 회신기한 오름차순→건ID·조치순번 | 제목링크→상세의 해당조치 |
| 확정 대기 | 연도/구분, 제목, 대상, 담당, 연한, 상태 | 연도 내림차순→건ID | 상세 결과영역 |
| 30일 안 삭제예정 | 제목, 확정일, 만료예정일, 남은일수, 미완료조치수, 보류여부 | 만료일 오름차순→건ID | 상세 보존요약 |

보류중도 원래 만료일 기준 임박이면 표시하되 “삭제 보류—자동삭제 안함” 명시. 이미 만료되고 미처리된 건은 같은 표 안 상단에 “삭제 지연”으로 구분해 놓쳐도 완료처럼 보이지 않게 한다(표현추천, 새 알림서비스 없음). 종결·조치미완료만으로 임박목록을 제외하지 않는다. 임박 계산은 서버와 동일 KST 정책, U1 미결정이면 “만료계산 정책 확인 필요”, 임의 날짜 없음.

- 버튼: 모든 역할 “건 목록”; 모든 역할 “건 등록”은 건 상세의 신규모드로 이동(다섯째 화면 아님). 파트장/관리자도 행에서 즉시확정/일괄삭제하지 않는다. 보류 변경은 관리자 관리화면에서 한다.
- 빈상태: “회신기한이 지난 조치요구가 없습니다”; 권한상 없는 다른표는 빈표조차 만들지 않는다. 로딩은 같은 표영역 skeleton 대신 한줄 “불러오는 중”, 완료 후 건수만 공지.

## 3. 건 목록

### 영역과 컬럼

제목행 `건 목록` + `건 등록`. 다음 줄 원문 필터 **연도/구분/상태/기한초과/삭제임박**, 검색, 적용/모두지우기. 연도는 선택형, 구분/상태는 원문값, 두 조건은 체크박스(기한초과=미완료 조치의 기한이 지난 건 추천). 활성필터칩은 필터바 아래, 현재 검색조건을 설명한다. 새 고급 AND/OR·AI 필터 없음.

조밀 표 추천 컬럼 순서:
`연도 | 구분 | 제목 | 대상 | 담당 | 상태 | 회신기한 | 보존연한 | 만료예정일·보류 | 문서번호 | 서가·철번호`.
- 제목은 건 상세 링크이자 행 머리글. 제목/상태 핵심열 고정, 날짜/연수 폭 고정, 설명열 유연. 긴제목 줄바꿈 허용; tooltip만으로 정보 제공하지 않는다. 행 전체 클릭은 보조이며 링크가 정식 진입점, 버튼/텍스트선택 시 행클릭 불발.
- 기본 정렬 `연도 내림차순→건ID`, 조작가능 정렬은 연도/제목/회신기한/만료일(없는 값은 뒤). 오름→내림→기본복귀 순환. `aria-sort`는 **th**에만, 정렬버튼명에 다음동작 포함. 모든 날짜 KST 일자.
- 기한 컬럼은 미완료조치의 가장 빠른 회신기한 요약, 상세에서 모든 조치 확인. 보류/초과/자료삭제됨은 텍스트 병기. 자료삭제됨 F02에도 목록·서가/철번호·결과한줄 접근은 남는다. 종이철함 폐기를 프로그램이 대신하지 않는다.
- 헤더 sticky, 제목열 sticky는 확대시 본문폭을 가리면 해제. 표를 region으로 감싸 가로스크롤하고 보이는 스크롤바/“표 가로 이동” 이름 제공. body 전체 강제가로스크롤 금지. 1366/1920에서 밀도검토, 200%에서는 필터 세로쌓기+표영역만 가로스크롤.
- 페이지크기 기본50, 선택25/50/100, 이전/다음·현재쪽/총건수 텍스트. 무한스크롤 없음. 페이지이동 뒤 표 caption에 포커스/결과공지, 검색입력 focus를 불필요하게 빼앗지 않는다.
- role별 보기 동일(감사파트 모든 건). 관리자 전용 백업/삭제 버튼을 표에 늘어놓지 않는다. 삭제임박은 필터이지 신규화면 아님.

빈상태 구별: 최초 데이터없음→“등록된 건이 없습니다”+건등록; 조건0건→“조건에 맞는 건이 없습니다”+조건지우기. 사용자가 입력한 raw 검색어를 오류로그나 페이지 제목에 인용하지 않는다.

## 4. 건 상세 (등록/편집 포함)

### 4.1 레이아웃

상단 `목록으로 | 건 상세 | 가상 표식` 후 제목, 연도/구분/담당. 다음 한줄 요약에 **기록상태 / 조치진행 n개 중 n개 완료 / 확정일 / 연한·만료일 / 보류 / 실제삭제현황**을 분리한다. 요약값은 A CaseView에서 계산하며 UI가 별도 만료·권한 로직을 갖지 않는다.

넓은 폭(예 1280px 이상) 왼쪽 약2/3에 다섯 묶음, 오른쪽 약1/3에 시간순이력. 작은폭/200%는 이력을 맨 아래로. 복수 내부 독립스크롤을 최소화하고 페이지가 기본스크롤. “건정보 / 결과 / 조치요구·이행 / 자료 / 이력” 본문내 앵커 제공, 새 화면/카드가 아니다.

### 4.2 다섯 묶음의 필드·행동

| 묶음 | 영역/컬럼 | 행동과 노출 |
|---|---|---|
| 건 | 연도, 구분, 제목, 대상, 담당, 서가, 철번호, 연한, 확정일(읽기), 상태(읽기), 보류여부·사유(읽기) | 전 역할 초안저장/필드수정 범위는 서버 capability. 연한담당은 확정전만; 과거확정후 취소로 권한복원하지 않는 추천 |
| 결과 | 문서번호, 결과한줄, 결과본문, 확정자(읽기) | 저장과 결과확정 분리. 파트장/관리자만 확정·취소. 확정결과 실질수정은 취소후 추천 |
| 조치요구 | 순번, 제목, 유형, 대상부서, 요구일, 회신기한, 내용, 조치상태 | 전 역할 “조치요구 추가”. 요구중/회신수신/이행완료 명칭은 추천값. 행 펼침은 동일화면이며 화살표버튼 aria-expanded |
| 이행 | 각 조치 아래 일시, 기록자, 상태변화, 회신본문, 확인본문 | “회신 기록”과 “이행 확인” 버튼 분리. 회신은 피감부서에서 받아 감사파트가 입력, 직접로그인 없음. 확인은 이행확인이지 진술확인서/자백 아님 |
| 자료 | 종류, 표시이름, 저장위치, 등록일, 등록자, 삭제일·상태 | 전 역할 자료추가(서버 허용시에만). 확정전 “첨부 빼기”, 확정후 연한전 관리자만 “파일 삭제”. 위치복사만, 미리보기/다운로드/본문읽기 없음 |

잔존필드(제목/대상/한줄/조치제목/자료명/사유) 옆 도움말: **“연한 후에도 남습니다. 개인식별정보·진술·민감한 상세내용을 적지 마세요.”** 결과본문/조치내용/회신·확인본문은 “만료 후 비워짐”. 서버도 길이/허용값 검증하되 자동으로 완벽 비식별화한다는 보장 없음.

상세에는 “초안 저장은 결과 확정이 아닙니다”, “결과 확정은 징계확정·전자결재가 아닙니다”, “종결은 자료삭제가 아닙니다”를 관련행동 근처에 간결히 안내한다. 계획·조사 완료 자동판정/서명·확인서 필수조건을 만들지 않는다.

자료 안내 원문 유지: **“이 위치의 파일은 사용자 컴퓨터의 나스카로 연다.”** 경로는 텍스트로 읽고 명시적 복사만 가능. server StorageKey 노출/직접 지정 없음. 경로를 브라우저 자동 file://로 열지 않는다. 삭제된 줄은 이름/등록정보/삭제일과 `삭제됨—복구되지 않음`, 위치는 `삭제됨`으로 대체(원래 경로 tooltip/DOM 숨김값도 없음). 누락파일은 `파일 없음—확인 필요`, 미등록이면 `등록된 자료 없음`으로 구별한다.

### 4.3 시간순 이력

등록부터 삭제까지 **과거→현재 오름차순** 고정 기본, `(At, Seq)`로 안정정렬. 이행과 이력은 같은 At/행위자. 행 형식 `KST 일시 | 행위 | 대상·조치순번 | 한줄 적요 | 행위자`. 동일 초에 여러 건이면 Seq로 정렬하고 순서를 구분한다. 마지막으로 이동 링크/이전이력 더보기는 같은화면, 이력수정·삭제·과거본문재현 없음.

- 대상 링크는 현재 조치/자료 영역으로 이동. 삭제자료도 잔존 메타행으로 이동하며 끊어진 원문링크 없음.
- 적요는 중립 템플릿/연수 앞뒤/상태만. 본문원값·파일경로·비밀번호·raw 검색어 복제금지. 본문 펼쳐보기 기능 없음.
- 이력검증 중은 “이력 확인 중”, 검증실패는 상단 고정 **이력 훼손—기록의 신뢰성을 확인할 수 없습니다**와 조회전용 안내. 훼손 상태에서 확정/종결/저장/삭제성공버튼을 활성화하지 않는 기술권고(A §10).
- 도움말: “단순 행변경을 확인하는 해시체인입니다. 꼬리와 기준값 동시변경·전체 재계산 등 모든 관리자 변조를 탐지하지는 못합니다.” 무결성보증/변조불가 배지 금지.

### 4.4 위험행위 확인

일반 `저장`은 primary, 별도 구역 `결과 확정 / 확정 취소 / 종결`, 관리자 `파일 삭제`는 위험색+명확한 대상. 비권한 버튼 숨김. `보류/해제`는 관리화면의 해당건으로 이동하는 관리자 전용 링크; 상세에는 현재 보류사실을 모두에게 보여준다.

| 행동 | 확인내용 | 필수 입력/실패 |
|---|---|---|
| 결과확정 | 연한·확정일기산·현재결과, 저장과 차이 | 연한없음422 필드링크; 사유를 임의 필수화하지 않음 |
| 확정취소 | 기존 조치/이력 유지, 이미 지운 파일 복구없음, 기산정책 U1 | **사유필수**; U1 미정이면 정책확인 안내/진행차단 |
| 종결 | 미완료조치수, 종결은 삭제아님 | 추천규칙상 미완료면 차단, 무조치면 명시확인 |
| 확정후 연한변경 | 기존→새 연수, 만료임박/이미지움 경고 | **사유필수**, 이미삭제복구없음 |
| 파일삭제 | 정확한 가상자료 표시이름/건, 파일만·본문유지, 복구불가 | 확정후 연한전은 **관리자+사유필수**, 보류중 차단추천 |
| 첨부빼기 | 확정전 첨부만, 자료행/이력남음 | 과거확정이 있으면 차단추천, 사유 원문필수로 확대안함 |

확인 대화상자는 첫포커스를 취소/설명에, 위험확인버튼을 Enter 기본값으로 만들지 않는다. 편집값이 남은 채 목록이동/닫기를 시도하면 저장하지 않은 입력 경고를 제공하고 자동저장은 하지 않는다. 확인한 후 최신 snapshot/Version을 서버 재검사, 클라이언트 확인만으로 허가하지 않는다. 중복클릭 disabled/“처리 중”+같은 requestId; 네트워크 단절시 결과모름을 실패확정처럼 표시하지 않고 재접속해 receipt/최신상태를 확인한다.

삭제접수202는 “삭제 작업 접수됨”일 뿐 완료가 아니다. jobId로 진행을 조회하고 개별 실패코드는 상태응답에서 표시한다. 삭제부분실패: 상세상단 `삭제 미완료: 본문 삭제됨, 파일 1건 재처리 대기`처럼 실제 확인된 값만 표시. 파일별 성공일만 표시하고 실패파일 위치는 재처리에 필요한 동안 보존. 원래 업무상태 유지, 전체 `자료삭제됨` 금지. 재시작 후 `중단된 삭제 작업을 확인·재처리 중` 안내, job이 완료될 때만 최종상태 전환. 경로/예외전문은 오류문구에 내보내지 않는다.

## 5. 관리 (관리자 전용)

탭/URL/API 모두 관리자만. 다른 역할 직접진입403, 내부 링크가 보여도 우회허용 안함. 한 화면 안 세 section, 별도 관리서비스/다섯째 업무화면 없음.

| 영역 | 표/입력 | 행동·오류회복 |
|---|---|---|
| 계정 | 비식별사용자명, 로그인명, 역할, 활성여부, 마지막관리자 여부 | 만들기/끄기/비번초기화. 임시비밀 한 번 전달·강제변경, 구세션폐기. 평문 저장/고정비번없음. 마지막활성관리자 끄기차단 |
| 내부 백업 | 승인된 내부디스크 목적지, 최근작업 시각·상태 | “백업 시작”; common gate로 변경잠시대기 안내, DB snapshot+files 함께. 성공/실패·미완료 구분. 실패본 완료이름 금지, 경로 전문 이력복사 없음 |
| 삭제 보류 | 건제목/상태, 원래만료일, 보류여부·사유, 최근설정/해제시각 | 건검색은 기존검색범위·POST, “보류 설정/해제”. 사유는 비식별·최소. 해제시 이미만료면 다음처리대상 경고, 이전삭제복구없음 |

백업은 암호화해도 연한삭제 해결이 아님을 짧게 안내. U2 정책미결정이면 “백업 보관·폐기 운영기준 확인 필요”, 무기한보관 기본/자동정리 설정UI를 만들지 않는다. 복구는 원문에 없던 새 제품기능으로 이 화면에 추가하지 않는다. A §11의 **오프라인 운영 복구절차**로 두고 최신 삭제/보류 기준 미확보이면 일반접속을 열지 않는다.

보류경합: 클릭 즉시 보류중으로 바꾸지 않고 서버 commit 응답 후 표시. 선행삭제가 있었으면 `보류 설정됨. 이미 삭제된 자료 n건은 복구되지 않습니다`. 보류 commit이 먼저면 이후삭제가 없어야 한다. 보류해제는 “유예기간 없음, 이미만료면 처리대상” 설명+명시확인. 설정/해제 일시는 이력과 동일 KST.

공통 본인비밀번호 대화상자는 세 역할 모두 헤더에서 접근, 현재비밀 확인→새비밀→기존세션폐기→재로그인. 변경/초기화 폼의 값을 오류요약/로그에 복제하지 않는다. 로그인폼은 공통 인증화면이며 MFA·SSO·메일발송을 임의로 추가하지 않는다.

## 6. 키보드·접근성·오류상태

### 6.1 키보드·스크린리더

- 논리 Tab: 건너뛰기(본문)→헤더→제목/오류→필터→표 링크·행동→페이지이동→이력. DOM과 시각순서 동일. div 전체를 억지 tabstop/grid로 만들지 않는다.
- 링크는 **Enter/클릭만 이동**, 포커스·화살표만으로 화면이동 금지. 버튼은 기본 Enter/Space. select·입력 화살표는 브라우저 기본. 명시적 조치펼침버튼만 aria-expanded 변경. 별도 `/`/단일문자 글로벌 단축키 기본 미채택.
- Esc는 열린 팝오버/대화상자만 닫고 서버에 제출하지 않는다. 입력중 페이지 전체를 초기화하지 않으며 미저장입력 있는 닫기는 확인한다. 대화상자 focus trap, Esc/취소 후 여는버튼으로 복귀; 성공 후 변경된 요약영역으로 복귀·공지.
- sticky header/열에 포커스링 안 가려지게 scroll-margin, 최소2px outline+offset. “outline:none” 금지. 표에 caption, th scope col/row, 정렬정보는 th aria-sort. 폼 label/설명/오류 aria-describedby/aria-invalid.
- 저장 성공·건수변경은 role=status/aria-live=polite. 오류요약은 role=alert, tabindex=-1로 이동하고 필드링크 제공; 무한중복 낭독 금지. 처리중 영역 aria-busy, 타이머마다 전체표 재낭독 금지.
- 200% 확대/좁은폭: 헤더 접속가능, 필터 단일열, 상세이력 아래, 표 및 필요한 한줄헤더 영역에만 제한 수평스크롤. 콘텐츠누락/버튼겹침/키보드트랩 없어야 한다. reduced-motion 지원, 필수 애니메이션 없음.
- Windows 내레이터/NVDA 수동확인 목표: 표행 제목/상태/정렬/오류요약/보류·부분실패 구별. **이번 실행 안함.**

### 6.2 상태별 문구와 복귀동작

| 상태/코드(A §12) | 표시 | 사용자행동·포커스 |
|---|---|---|
| 초기/필터 빈목록 | 등록없음 / 조건결과없음 구별 | 건등록 / 조건지우기 |
| 로딩 | 불러오는 중, aria-busy | 이전콘텐츠를 성공새값으로 바꾸지 않음 |
| 본문 최초없음 | 아직 작성된 본문 없음 | 권한시 작성 |
| 연한후 본문삭제 | 보존 만료로 본문 삭제 | 원값복원 버튼없음 |
| 400 CSRF | 세션/요청을 확인할 수 없음 | 재로그인·최신보기, 자동재전송금지 |
| 401 | 로그인 만료/세션폐기 | 인증복귀, raw 본문 영구저장금지 |
| 403 | 이 작업 권한 없음 | 허용된 목록/할일로; 금지데이터 비표시 |
| 404 | 건을 찾을 수 없음 | 목록으로, 유사건정보 노출없음 |
| 409 STALE_VERSION | 다른 사용자가 먼저 변경 | 현재입력 메모리 유지, 최신값 보기 후 수동재제출 |
| 409 HOLD_ACTIVE | 삭제 보류 중—삭제하지 않음 | 관리자 검토안내, 해제 자동실행없음 |

권한변경·세션폐기로 401/403이 되면 capability를 새로 받아 그린다. 클라이언트가 숨긴버튼만 믿지 않는다. 반환코드와 상태문구는 A 정의에서 파생하도록 계약시험으로 맞춘다. 409에서 raw 입력을 URL·로컬스토리지·오류보고에 넣지 않는다. 서버중단 시 입력 손실 가능성을 정직하게 안내하며 오프라인 PWA/자동저장기능은 추가하지 않는다.

## 7. 공통 가상 fixture: 정확히 두 건

**아래 전부 가상이며 실명·원문 예시 이름·실부서·민감자료를 재사용하지 않는다. 문서상 데이터 정의일 뿐 실제 DB/파일 생성 없음.** 기준일은 2026-11-06 KST로 고정해 계획시험이 날짜에 흔들리지 않게 한다. 연수·날짜는 회사 보존정책이 아니라 가상 검증값. 다른 담당 fixture와 이름이 다르면 이 두 문서 범위에서만 F01/F02를 일관되게 사용하고 별도 데이터를 추가하지 않는다.

가상역할 주체는 가상담당-가/가상파트장-가/가상관리자-가(사람 실명 아님). 예시 비밀번호·토큰·실경로는 기재하지 않는다.

- 할 일: 담당은 F01 기한초과 조치1행, 파트장/관리자도 초과표에서 F01. 기본 fixture에는 확정대기/30일임박 행없음→빈상태. F01만 초기화/변형해 초안·임박·보류·오류를 시험한다.
- 건 목록: 두 행, F02 자료삭제됨에도 검색·목록/철번호 남음. 필터로 기한초과=F01, 상태자료삭제됨=F02 확인 계획.
- 상세: F01 회신기록→회신수신(완료아님)→이행확인→종결 흐름. F02 삭제본문·파일경로없음·결과한줄/이력잔존. 취소/연장 시에도 F02 기삭제자료복구없음. 취소 후에도 PurgedAt을 유지하므로 표시상태는 자료삭제됨이고 시간순이력에 취소가 추가된다.
- 관리: F01을 같은 데이터에서 보류/해제·삭제실패·백업경합으로 변형, 테스트 뒤 초기화. F02를 낡은백업복구/해시변조 계약에 사용. 상시 세번째 건 생성하지 않는다.
- A E1~E7/X1~X10은 이 fixture를 참조. 잠김파일/여러첨부 부분실패를 시험할 때 F01의 자료만 임시 변형하며 새 감사건을 늘리지 않는다.
