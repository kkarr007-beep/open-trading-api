# 감사기록 시스템 설계서

전달일: 2026-11-06
상태: 설계 1~4와 반영 방식 승인. 이 문서가 구현 범위의 전부다.
받는 곳: 그록봇. 시스템 구현 담당.
출처: 대표님 메시지 t63u (원문 보존). t65u에서 품질·UI 개선·좋은 OSS 참고는 후속 승인되었으나, 본 파일은 t63u 원설계 본문을 빠짐없이 보존한다.

## 지시

이 설계서만 구현한다. 설계에 없는 기능, 화면, 연동은 넣지 않는다.
실제 감사 자료, 개인정보, 나스카 문서, 포털 비밀번호를 요구하거나 저장하지 않는다. 예시 데이터만 쓴다.
인터넷에 배포하거나 클라우드에 올리지 않는다.
결과물은 인터넷이 없는 Windows 컴퓨터 한 대에 설치하고, 같은 내부망의 다른 컴퓨터에서는 브라우저로만 접속하는 프로그램이다.

## 1. 두는 곳

감사파트 컴퓨터 한 대가 서버다. 담당자 개인 업무 컴퓨터와 겸하지 않는다.
다른 사람은 프로그램을 설치하지 않고, 내부망 주소로 브라우저에 접속한다.
실행 중 외부망을 호출하지 않는다. 글꼴은 Windows에 있는 맑은 고딕만 쓴다. 인터넷 글꼴과 외부 스크립트는 쓰지 않는다.
계정은 사내 포털, SSO와 연결하지 않는다. 감사파트가 직접 만든다.
데이터와 원문은 그 컴퓨터 안에만 둔다.

폴더:

```text
감사기록\
app\ 프로그램
data\ 항목 데이터 파일 하나 (SQLite)
files\ 결과원문, 증빙, 회신첨부
backup\ 관리자가 남기는 내부 복사본
```

팀원은 데이터 파일을 직접 열지 않는다. 서버 프로그램만 파일을 다룬다.

## 2. 기술

- 언어는 C#이다. ASP.NET Core로 화면과 저장을 한 프로그램에서 제공한다.
- 항목 데이터는 SQLite 파일 하나다. 별도의 데이터베이스 서버는 두지 않는다.
- 원문 파일은 데이터베이스 안에 넣지 않고 files 폴더에 둔다.
- Java, Python, Docker, 다른 오픈소스 제품 전체를 가져오지 않는다.
- 깃의 감사로그 라이브러리를 가져오지 않는다. 그 라이브러리는 고치기 전후 본문을 통째로 남겨, 아래 보존 규칙과 충돌한다.

## 3. 나스카

결과서 원문은 나스카로 암호화되어 있고, 포털에 로그인된 사용자 컴퓨터에서만 열린다.
프로그램은 암호를 풀지 않는다. 문서 내용을 읽지 않는다. 화면 안에서 미리보기, PDF 변환, 본문 검색을 하지 않는다.
서버를 나스카 복호화 대상으로 등록하지 않는다.
자료에는 종류, 표시 이름, 저장 위치, 등록일, 등록자, 삭제일만 둔다.
사용자가 원문을 보려면 적힌 위치를 자기 컴퓨터에서 연다. 열림 여부는 나스카가 판단한다.

구현 뒤 사람이 할 확인 한 가지. 암호화된 파일 하나를 서버 폴더에 넣고, 다른 담당자 컴퓨터에서 포털 로그인 후 열리는지 본다. 프로그램이 이 시험을 대신하지 않는다.

## 4. 쓰는 사람과 역할

1차 사용자는 감사파트만이다. 피감부서는 로그인하지 않는다. 회신은 지금처럼 받아 담당이 입력한다.
감사파트 안에서는 모든 건을 다 본다. 자기 건만 보이게 나누지 않는다.

```
| 하는 일                         | 담당    | 파트장       | 관리자       |
| ---------------------------- | ----- | --------- | --------- |
| 목록과 이력 열람                    | 가능    | 가능        | 가능        |
| 건 등록, 초안, 조치요구, 회신 기록, 자료 추가 | 가능    | 가능        | 가능        |
| 결과 확정, 확정 취소, 종결             | 불가    | 가능        | 가능        |
| 보존연한 입력                      | 확정 전만 | 확정 후에도 가능 | 확정 후에도 가능 |
| 확정 전 첨부 빼기                   | 가능    | 가능        | 가능        |
| 확정 후, 연한 전 파일 삭제             | 불가    | 불가        | 사유 필수     |
| 삭제 보류 설정과 해제                 | 불가    | 불가        | 가능        |
| 계정, 백업, 비밀번호 초기화             | 불가    | 불가        | 가능        |
| 이력 수정, 이력 삭제                 | 불가    | 불가        | 불가        |
```

관리자는 파트장의 업무 권한을 포함한다. 계정, 백업, 삭제 보류가 더해진다. 한 사람이 겸임할 수 있다.
본인 비밀번호 변경은 세 역할 모두 가능하다.

규칙:

- 보존연한이 없으면 확정할 수 없다. 확정일이 연한의 기산일이다.
- 확정 취소, 확정 후 연한 변경, 연한 전 파일 삭제는 사유가 필수다. 이력에는 "5년 → 7년"처럼 앞뒤 값만 적는다. 본문은 적지 않는다.
- 종결은 조치가 끝났다는 표시다. 종결해도 파일과 본문은 연한까지 남는다.
- 파일이 이미 지워진 뒤 확정을 취소해도 파일은 되살리지 않는다. 그 사실을 이력에 남긴다.
- 삭제 보류 중인 건은 연한이 지나도 지우지 않는다. 보류를 푼 뒤에 지운다. 설정과 해제한 시각을 이력에 남긴다.
- 종이 철함은 프로그램이 폐기하지 않는다. 서가와 철번호는 목록에 남긴다.

## 5. 기록 다섯 묶음

한 건은 아래 다섯 묶음이다. 화면에서는 시간 순 이력 하나로 이어 보여 준다.

건. 하나.

- 연도
- 구분: 업무진단 또는 준법감사
- 제목
- 대상
- 담당
- 서가, 철번호
- 보존연한
- 결과확정일
- 상태: 초안, 확정, 조치중, 종결, 자료삭제됨
- 삭제 보류 여부와 사유

결과. 건마다 하나.

- 문서번호
- 결과 한 줄. 짧게만 적게 하고, 연한 뒤에도 남긴다.
- 결과 본문. 연한 뒤에 비운다.
- 확정자

조치요구. 여러 개.

- 순번
- 제목
- 유형: 지적, 개선요구, 권고
- 대상 부서
- 요구일
- 회신기한
- 내용. 연한 뒤에 비운다.
- 상태

이행. 조치요구 아래에 쌓되, 건의 이력에도 같은 시각으로 올라간다.

- 일시
- 기록자
- 상태 변화. 남긴다.
- 회신 본문, 확인 본문. 연한 뒤에 비운다.

자료. 여러 개.

- 종류: 결과원문, 증빙, 회신첨부
- 표시 이름
- 저장 위치
- 등록일, 등록자
- 삭제일. 파일은 지워도 이 줄은 남긴다.

이력. 프로그램이 추가만 한다. 화면에서 고치거나 지우는 기능은 없다.

- 일시
- 행위: 등록, 결과확정, 확정취소, 조치요구, 회신, 이행확인, 종결, 연한변경, 보류, 보류해제, 자료삭제, 수정
- 대상
- 제목 또는 한 줄 적요
- 행위자

이력에 본문 전체를 복사하지 않는다. 복사하면 본문을 비워도 내용이 이력에 남는다.
각 이력 줄은 앞줄의 지문(SHA-256)을 가진다. 누군가 데이터 파일을 직접 고치면 화면 상단에 이력 훼손으로 표시한다. 외부 서비스는 쓰지 않는다.

## 6. 보존연한

연한은 건마다 하나만 둔다. 기산일은 결과확정일이다.
만료되면 지우는 것:

- 결과 본문
- 조치요구 내용
- 회신 본문, 확인 본문
- 원문, 증빙, 회신첨부 파일과 그 저장 위치

남기는 것:

- 건의 목록 정보, 결과 한 줄
- 조치요구의 제목, 유형, 대상, 날짜, 상태
- 자료의 이름과 삭제일
- 이력 전체

파일은 휴지통에 넣지 않고 삭제한다.
서버 컴퓨터가 꺼져 있으면 그 시각에 지울 수 없다. 프로그램이 켜져 있을 때 만료분을 처리하고, 처리 시각을 이력에 남긴다.
삭제 보류 건은 건너뛴다.

## 7. 화면

화면은 네 개만 만든다.

할 일.

- 차트, 그래프, 카드 나열을 만들지 않는다.
- 담당에게는 회신기한이 지난 조치요구.
- 파트장과 관리자에게는 확정 대기, 기한 초과, 30일 안에 삭제될 건.
- 줄을 누르면 그 건으로 이동한다.

건 목록.

- 조밀한 표.
- 필터: 연도, 구분, 상태, 기한초과, 삭제임박.
- 검색: 제목, 대상, 문서번호, 철번호.

건 상세.

- 위 다섯 묶음의 항목.
- 오른쪽 또는 아래에는 시간 순 이력. 등록부터 삭제까지 한 줄로 이어 보인다.
- 자료는 내용 대신 위치만 보여 준다. "이 위치의 파일은 사용자 컴퓨터의 나스카로 연다"는 안내 한 줄을 둔다.
- 권한 없는 버튼은 보이지 않는다.

관리.

- 관리자에게만 보인다.
- 계정 만들기, 끄기, 비밀번호 초기화.
- 백업: data 파일과 files 폴더를 관리자가 지정한 내부 디스크 경로로 복사한다. 인터넷 백업은 없다.
- 삭제 보류 설정과 해제.

## 8. 하지 않는 것

- 피감부서 로그인과 직접 회신
- 워크페이퍼 전문 보관
- 전자결재
- 포털 계정과 우리 계정을 묶는 일
- 본문 검색, 문서 미리보기, 서버에서 나스카 해제
- 자동으로 종이 폐기
- 인공지능 요약, 위험 라이브러리, 다른 시스템 연동
- 클라우드 배포, 외부망 호출
- 이력 수정과 삭제
- 오픈소스 제품 통째 반입

## 9. 예시 데이터

구현 확인용으로 가짜 건 둘만 넣는다.

- 2024 업무진단. 대상 "예시조직". 조치요구 하나. 회신기한은 과거. 파일은 빈 예시 파일.
- 2022 준법감사. 보존연한이 지나 자료삭제됨 상태. 결과 한 줄과 이력만 있고 본문과 파일은 없다.

실명, 실제 부서, 실제 문서 내용을 넣지 않는다.

## 10. 끝나는 기준

아래가 되면 구현이 끝난 것이다.

1. 감사파트 컴퓨터에 설치하고, 다른 컴퓨터의 브라우저에서 접속된다.
2. 실행 중 외부 주소로 접속하지 않는다.
3. 담당은 확정과 종결을 할 수 없고, 관리자만 연한 전 삭제와 보류를 할 수 있다.
4. 건을 열면 등록, 결과, 조치요구, 회신, 삭제가 시간 순으로 보인다.
5. 연한이 지난 건은 파일과 본문이 없고, 목록과 이력은 남는다.
6. 이력 줄을 데이터베이스에서 고치면 화면에 훼손이 표시된다.
7. 프로그램은 문서 파일을 열어 내용을 읽지 않는다.
