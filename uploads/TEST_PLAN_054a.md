## 2. 시험 전제와 환경

- 환경 A(자동): Windows 10/11 x64 또는 Windows Server, 대상 .NET 버전 [확인필요 Q15], Windows CI 또는 격리 로컬 PC. 인터넷 차단 상태에서 실행(차단 자체가 시험 조건).
- 환경 B(사람): 실제 감사파트 서버 PC 1대 + 다른 내부망 PC 1대 이상, 사내 브라우저(Edge/Chrome 버전 [확인필요 Q13]), NASCA 포털 로그인 가능한 담당자 PC.
- 시간: 서버는 `IClock` 같은 시간 주입 지점이 있어야 기산·만료·윤년 시험이 자동화 가능 [전제]. 없으면 OS 시계 변경 시험만 가능(사람, 위험).
- box(Linux)는 계획·문서 작성용. 여기서 돌린 어떤 결과도 출시 증적으로 쓰지 않는다.

- NASCA 시험 파일은 사람시험 담당자가 내용 무관한 테스트 문서를 준비. QA·봇은 내용을 받지도 보지도 않음.
- 계정: 시험용 `담당A, 담당B, 파트장P, 관리자M, 겸임X(파트장+관리자)`, 비밀번호는 시험 PC에서만 생성.
- S2 값: 원문에 확정일·연한 값이 지정되지 않음. 2026-11 기준 만료 상태가 되려면 짧은 연한(예: ≤3년)이면 충족 가능 [확인필요 Q9]. 시드를 "직접 삭제된 상태로 주입"하면 이력·체인이 실제 처리와 달라질 수 있으므로 시드도 정상 흐름(확정→만료처리)으로 생성하는 것을 권장 [개선].

## 4. 권한·보안

### 4.0 시간순 이력 (T-HIS)
- T-HIS-01: S1 흐름(등록→결과확정→조치요구→회신→이행확인→종결) 후 상세 이력이 시각 오름차순 한 줄로 보임.
- T-HIS-02: 이행 기록이 조치요구 아래와 건 이력에 같은 시각으로 표시.
- T-HIS-03: 만료 처리 후 '자료삭제' 줄이 처리 시각으로 마지막에 붙음, 이력에 본문 복사 없음.

- T-SES-03 역할 변경(관리자→담당) 시 기존 세션의 다음 요청부터 새 권한 적용(캐시된 역할 클레임 사용 금지).
- T-SES-04 [검토 제안] 관리자가 본인 계정 끄기·마지막 관리자 끄기/강등 → 거부 또는 경고. 원문에 없어 **제안**, 기대값 미확인(Q19).
- T-SES-01~03은 E3 우회 방지와 겹치므로 실패 시 [QA 권고]가 아닌 실질 결함으로 보고.
- 이하 **[QA 권고 게이트]** (원문 외, 출시 반영은 총괄/대표님 결정):
- T-SEC-01 인증: 실패 메시지 동일, 잠금/지연 [확인필요 Q2], 비밀번호 해시 저장(평문·가역 없음), 로그에 비번 없음.
- T-CSRF-01: 모든 상태변경 요청 antiforgery 토큰 필수, 토큰 없음/타 세션 → 400, 쿠키 HttpOnly·SameSite, GET 상태변경 불가, 다른 내부망 출처 자동 POST 거부. 실패는 실질 보안 결함이므로 원문에 없어도 **출시 가능으로 간주하지 않고** 결정 요청.
- T-SEC-02 전송: HTTP 평문이면 비번·본문 노출 위험. TLS 여부 [확인필요 Q3].
- T-SEC-03 입력: XSS(제목·적요·사유), 표시 이름·저장 위치 경로 traversal(`..\`, UNC, 절대경로, ADS, 예약명), 업로드 크기 상한, 저장 위치가 다른 서버 경로 노출 안 함.
- T-PII-01 목록 검색(제목·대상·문서번호·철번호 = 허용 메타데이터)과 본문 검색 금지(§8)를 구분: 본문 단어 검색 0건(T-SCR-03 교차).
- T-PII-02 검색어가 URL 쿼리스트링·브라우저 기록에 남는지 확인. [검토 제안: UIO-U3]은 필터·검색의 URL 반영을 권고 → 검색어 잔존과 **충돌**, 정책 미정(Q18).
- T-PII-03 서버 접근 로그·오류 로그에 검색어·본문·경로·비번이 남지 않음.
- T-PII-04 이력 적요·오류 문구에 본문·전체 경로 복사 없음(WFR-F07, T-CHN-07 교차).
- T-SEC-04 헤더: CSP `default-src 'self'`, `nosniff`. 첨부 다운로드 기능은 원문에 없어 요구하지 않음(T-NAS-05에서 없음 확인).

### 4.2 NASCA·문서 내용 비열람 (T-NAS) — [원문] §3·§8·§10-7
허용 메타데이터: 종류, 표시 이름, 저장 위치, 등록일, 등록자, 삭제일(§3). 구분 원칙: 내용 바이트의 **단순 저장(업로드 쓰기)·백업 복사·삭제**는 허용 동작, **해석·추출**(파싱, 미리보기, 변환, 본문검색, 인덱싱, OCR, 썸네일)은 금지. 원문에 없는 기능(파일 해시, MIME 판별, 백신 연동, 첨부 다운로드)은 기본 요구로 넣지 않으며 승인 없이 추가되면 범위 위반(T-SCP-01).
- T-NAS-01: 의존성·코드에 PDF/Office/이미지 파서, OCR, 썸네일, FTS 인덱스 없음(SQLite FTS 테이블 없음).
- T-NAS-02: Windows Process Monitor로 업로드·목록·상세·백업·만료 중 `files\` 접근 → 쓰기(업로드), 복사(백업), 삭제(만료/관리자) 외 읽기 없음.
- T-NAS-03: 자료 화면에 허용 메타데이터 6종만, 안내문 "이 위치의 파일은 사용자 컴퓨터의 나스카로 연다" 정확히 1줄.
- T-NAS-04: 본문 검색 없음(목록 검색 4필드만) — T-SCR-03과 교차.
- T-NAS-05: 미리보기·변환·다운로드 엔드포인트 없음(라우트 목록).
- T-NAS-06 (사람·설정증거): 서버가 NASCA 복호화 대상으로 **등록되지 않았음**을 등록 대상 목록/설정 화면 등 설정 증거로 확인. 서버에서 NASCA 문서를 직접 열어보는 시험은 **하지 않는다**.
- T-NAS-H1 (사람 전용, §3): 암호화 파일 1개를 서버 폴더에 넣고 다른 담당자 PC에서 포털 로그인 후 열림 확인. 내용은 캡처·기록하지 않음.

## 5. 동시수정 (T-CON) — [원문 파생]
- T-CON-01 같은 건 담당A·파트장P 동시 편집 → 늦은 저장 409·안내, 덮어쓰기 없음(낙관적 잠금 [전제]).
- T-CON-02 확정과 첨부 빼기 동시 → 하나만 성공, 확정 후 첨부 빼기 거부.
- T-CON-03 확정취소↔만료처리, 보류설정↔만료처리 동시 → 보류 먼저 커밋 시 삭제 건너뜀, 어느 순서든 최종 상태·이력 일치.
- T-CON-04 이력과 업무 변경 같은 트랜잭션: 중간 예외 주입 시 둘 다 롤백.
- T-CON-05 이력 동시 추가 100건 → 체인 분기 없음(T-CHN-08 교차).
- T-CON-06 SQLite 잠김(`database is locked`) → 재시도 가능한 오류, 손상 없음.

### 6.3 이력 해시 체인 — 탐지 범위와 한계 (T-CHN)
[원문] §5: "각 이력 줄은 앞줄의 지문(SHA-256)을 가진다. 누군가 데이터 파일을 직접 고치면 화면 상단에 이력 훼손으로 표시한다." §10-6: "이력 줄을 데이터베이스에서 고치면 화면에 훼손이 표시된다."

**설계 주의(구현 확정 아님):** '다음 줄이 가진 앞줄 지문과 불일치'만으로는 **마지막 행·유일한 1행의 내용 수정**을 잡지 못한다(검사할 다음 줄이 없음). §10-6을 충족하려면 예컨대 각 행이 자기 내용+앞줄 지문으로 계산한 **현재행 지문을 저장하고 검증 시 재계산·대조**하는 식의 설계가 필요하다. 방식은 개발 쪽 결정, QA는 아래 결과로만 판정.

**E6 필수(자동, 실패 시 원문 완료판정 미완료)** — 원문 문구 "이력 줄을 데이터베이스에서 고치면"을 **행 내용 편집**으로 해석:
- T-CHN-01 중간 행의 일시·행위·대상·적요·행위자 중 1필드 수정 → 훼손 표시.
- T-CHN-02 **마지막 행** 내용 수정 → 훼손 표시.
- T-CHN-03 **이력이 1행뿐인 건/DB**에서 그 행 내용 수정 → 훼손 표시.

**추가 회귀/설계 권고(E6 필수 아님)** — 원문에서 명확하지 않은 범위. 실패는 [QA 권고]로 보고하고 E6 미완료로 단정하지 않음 [검토 제안: SEC-R1 V1.2~V1.4]:
- T-CHN-04 중간 행 삭제 → 표시 기대.
- T-CHN-05 행 순서 교환·중간 삽입 → 표시 기대.
- T-CHN-06 저장된 지문 칼럼만 수정 → 표시 기대.
- T-CHN-07 정상 운영(만료 본문 비우기, 확정취소, 보류) 후 오탐 0, 이력에 본문·경로·비번 없음 (오탐은 E6 품질 결함으로 보고).
- T-CHN-08 동시 추가 100건 후 체인 분기 없음(T-CON-05 교차).
- T-CHN-09 검증 시점·표시 위치 [확인필요 Q12]. 훼손 시 업무 쓰기 동결은 [검토 제안: SEC-R1 T3], 원문 아님.

**현 구조 탐지범위 밖(문서화로 허용, 과장 금지)** — DB 안 지문만으로는 원리상 못 잡음:
- T-CHN-L1 **마지막 행 삭제**: 남은 체인은 자체로 일관 → 독립 앵커 없으면 미탐지. (마지막 행 *내용 수정*은 T-CHN-02로 탐지 필수, 둘을 혼동하지 않음.)
- T-CHN-L2 변조 지점부터 끝까지 지문 전체 재계산: 비밀키 없는 SHA-256이므로 DB 쓰기 권한자가 일관 체인 재생성 가능 → 미탐지.
- T-CHN-L3 DB 파일 전체를 예전 백업으로 바꿔치기(롤백) → 미탐지.
- T-CHN-L4 서버/Windows 관리자 권한자의 변조 → 미탐지.
- 업무 테이블(건·결과 등) 직접 수정은 체인 대상 아님 → 원문 요구 밖, 미탐지 가능.
- [개선 제안, 승인 필요·출시판정 제외] 독립 앵커: 최신 지문·행 수를 **내부 오프라인 매체**(인쇄물, 별도 보관 이동식 매체, 담당 외 사람의 수기 기록)에 주기 보관. 외부 서비스·클라우드·인터넷 타임스탬프는 **해당 없음**(원문 §1·§8 위반).
- SEC-R1의 '같은 DB 안 head/lastSequence 보관 시 꼬리삭제 조건부 탐지'는 그 값도 같은 권한으로 바꿀 수 있어 독립 기준점이 아님. 조건부 회귀로만 둔다.
- QA 보고 문구: "이력 행 내용 수정(중간·마지막·유일행) 탐지 = E6 / 중간삭제·삽입·순서·지문수정 = 추가 회귀 / 꼬리삭제·전체재계산·롤백·관리자 권한 변조 = 현 구조 탐지범위 밖".

### 6.3a 확정취소·재확정 우회 방지 (T-RCF) — §4 규칙(USER_SPEC 기준) + [검토 제안: WFR-F01·F04, SEC-R3]
원문(USER_SPEC §4): 담당은 '확정 전만' 연한 입력, 확정 후 연한 변경·연한 전 파일삭제는 사유 필수(삭제는 관리자만), 파일이 이미 지워진 뒤 취소해도 되살리지 않음.
- T-RCF-01 공격흐름 A: 파트장 확정 → 파트장 확정취소 → **담당이** 첨부 빼기 → 파트장 재확정. 기대: 확정 이력이 한 번이라도 있는 건의 첨부 제거는 '확정 후 연한 전 삭제'(관리자·사유)로 취급되어 담당 거부. 정책 미정이면 **미확인**(Q16), 다만 사유·이력 없이 파일이 사라지면 **차단**.
- T-RCF-02 공격흐름 B: 확정 → 취소 → **담당이** 보존연한 7→3 축소 → 재확정 → 즉시 만료. 기대: 사유 없는 축소 불가, 이력에 '7년 → 3년'과 행위자. 담당 권한 재개방 여부는 **미확인**(Q16).
- T-RCF-03 공격흐름 C: 취소·재확정 반복으로 기산일 연장(연한 회피). 기대 기산일(최초 확정일 vs 재확정일)은 **미확인**(Q5, WFR-F04는 최초 유지 권고·대표 승인 필요). 어느 쪽이든 모든 확정·취소 시각이 이력에 남아야 함(필수).
- T-RCF-04 만료·조기삭제로 비운 본문·파일이 취소·재확정·연한 연장으로 **복원되지 않음**(USER_SPEC §4 필수). 파일 없음 사실 이력 기록.
- T-RCF-05 삭제 후 같은 건에 새 본문·첨부 재입력 허용 여부: **미확인**(Q16; WFR-F04·F10은 만료·미보류 건 재입력 차단 권고).

### 6.3b 보류·삭제 경합 (T-LCK) — §4·§6 + [검토 제안: SEC-R3 T2, WFR-F09]
건별 잠금·삭제 직전 재검증은 제안이며 구현 방식은 QA가 정하지 않는다. 순서 주입(테스트 훅/시간 주입 [전제])으로 결과만 판정.
| ID | 순서 | 기대 상태 |
|---|---|---|
| T-LCK-01 | 보류 커밋 → 만료 작업 판정 | 삭제 안 함, 본문·파일 유지(필수) |
| T-LCK-02 | 만료 작업이 대상 선정 → 보류 커밋 → 파일 삭제 직전 | 삭제 직전 재확인으로 중단 기대(TOCTOU). 재확인이 없어 삭제되면 **차단**(§6 '보류 건은 건너뛴다' 위반) |
| T-LCK-03 | 파일 삭제 시작(비가역) 후 보류 커밋 | 이미 지운 것은 복구 불가, 보류는 유효, 남은 파일은 중단, 이력에 순서 기록 |
| T-LCK-04 | 보류 해제 ↔ 만료 작업 동시 | 해제 커밋 후에만 삭제, 이력 '보류해제'가 '자료삭제'보다 앞 |
| T-LCK-05 | 관리자 조기삭제 ↔ 보류 설정 동시 | 보류 중 조기삭제 허용 여부 **미확인**(Q19; WFR-F09 권고=금지). 최종 상태와 이력이 일치해야 함(필수) |

### 6.3c 부분실패·재시작 (T-PND) — **'pending/삭제 미완료'는 원문 상태가 아님** [검토 제안: SEC-R3, WFR-F10]
원문 상태는 초안·확정·조치중·종결·자료삭제됨뿐. 미완료 표시를 새 상태값으로 둘지, 이력 적요로 둘지는 **미확인**(Q17). 아래는 표시 방식과 무관한 필수 결과.
- T-PND-01 파일 3개 중 1개 잠김 → '자료삭제됨' 거짓 표시 없음, 지운 파일만 삭제일.
- T-PND-02 처리 중 프로세스 강제종료 → 재시작 후 나머지 처리, 삭제일·이력 중복 없음(멱등).
- T-PND-03 재시도 2회 연속 실행 → 결과 동일, 이력 1회.
- T-PND-04 재시도 대기 중 보류 설정 → 재시도 중단(T-LCK 교차).

### 6.4 백업 일관성 (T-BAK) — [원문] §7: data 파일과 files 폴더를 관리자가 지정한 **내부 디스크 경로**로 복사
- T-BAK-01 지정한 내부 디스크 경로에 data+files 복사 완료, 인터넷 백업 경로 없음.
- T-BAK-02 사용 중 백업 후 백업 DB `PRAGMA integrity_check` ok + 체인 검증 통과(DB 무결성). WAL 사용 시 일관 스냅샷 방식 [전제].
- T-BAK-03 백업 중 업로드/삭제 병행 → 백업 DB의 자료 행(표시 이름·저장 위치·삭제일)과 백업 files 목록이 일치(논리 일관성).
- T-BAK-04 매니페스트는 **메타데이터만**(경로·이름·크기·수정시각·개수)으로 대조. 문서 내용 해시는 승인 없으므로 쓰지 않음.
- T-BAK-05 공간 부족·권한 없음 → 명확한 실패, 부분 백업이 성공처럼 남지 않음.
- T-BAK-06 (사람) 복원 리허설: 백업본으로 다른 폴더에서 기동해 S1·S2 확인. 절차·RPO/RTO [확인필요 Q7].
- T-BAK-07 [보존 위험 고지] 만료로 지운 본문·파일이 backup\·SQLite 자유 페이지/WAL에 남을 수 있음 → 처리 정책 [확인필요 Q8]. 원문 §10-5는 앱 데이터 기준이므로 미정이면 **보류**가 아니라 위험 고지로 기록.

### 6.5 복구 후 재노출 방지·잔존 (T-RST) — [검토 제안: SEC-R2·R4, WFR-F08] / [QA 권고 게이트]
원칙: 시험은 **합성 데이터(S1·S2 변형, `[가상]`)로만**. 봇·QA는 복구본의 문서 내용을 읽거나 열지 않는다(바이트 존재·메타데이터만 확인).
- T-RST-01 만료·조기삭제 **전** 백업 → 만료·조기삭제 실행 → 그 백업 복구. 기대: 사용자 로그인·서비스 공개 **전에** 최신 삭제·보류·조기삭제 기록이 재적용되어 삭제 본문·파일이 화면에 재노출되지 않음. 단순 '현재 날짜 기준 만료 재계산'만으로는 조기삭제를 놓침.
- T-RST-02 재적용 기준(최신 기록)을 확인할 수 없으면 일반 사용자 접근을 열지 않음(관리자 확인 대기).
- T-RST-03 복구본이 보류 해제를 모르는 낡은 상태일 때 보류 상태 처리 — 기대값 **미확인**(Q20).
- T-RST-04 스냅샷 동시점: 백업 중 업로드·삭제 병행 시 DB 자료 행과 files 메타가 같은 시점(T-BAK-03 교차). 실패본은 '완료'로 표시 안 됨.
- T-RST-05 WAL·자유 페이지·journal·temp에 지운 값이 남을 수 있음 — **논리 삭제 한계**로 문서화. QA는 '완전 파기'를 판정하지 않으며 잔존 바이트 복구 시도도 하지 않음. `secure_delete`·VACUUM·checkpoint 절차 존재 여부만 문서 확인 [SEC-R2 V2.4].

## 7. UI·글꼴 (T-SCR·T-FNT [원문], T-UI·T-KBD·T-A11Y [QA 권고 게이트])
- T-SCR-01 4화면만(라우트 목록). T-SCR-02 할 일: 표/목록 줄, 차트·그래프·카드 0, 역할별 내용(담당=기한 지난 조치요구, 파트장·관리자=확정대기·기한초과·30일 내 삭제), 줄 클릭으로 건 이동.

## 8. 설치·네트워크·범위·예시 (T-INS, T-NET, T-STK, T-SCP, T-FLD, T-SMP) — [원문]
- T-INS-01 인터넷 차단 서버 PC에 설치·첫 실행 성공(런타임 포함 여부 [확인필요 Q15]).

## 9. 출시 판정 기준
### 9.1 [원문 완료판정]
- **미완료(출시 불가)**: E1~E7 중 하나라도 실패, T-AUTH-01~11·B1·B2 실패, 외부요청 1건(T-NET-01~04), 문서 내용 해석·미리보기(T-NAS-01~05), 이력 수정·삭제 경로(T-AUTH-11), 만료 후 앱 데이터에 본문·파일 잔존(E5), 이력 행 내용 수정 미탐지(T-CHN-01·02·03), 확정취소 우회로 사유·이력 없는 삭제/연한축소(T-RCF-01·02), 삭제분 복원(T-RCF-04), 보류 무시 삭제(T-LCK-01·02), 실자료(T-SMP-04), 범위 외 기능(T-SCP-01), 동시수정 데이터 유실(T-CON-01~06).

- **미확인(기대값 미정)**: T-RET-03·04·07, T-EXP-01·05·09, T-BAK-06, T-SMP-03 값, T-FLD-02, T-CHN-09, T-RCF-01·02·03·05, T-LCK-05, T-PND 표시방식, T-RST-03, T-SES-04.

### 9.2 [QA 권고 출시 게이트·정책확인 필요] — 판정은 시스템 총괄/대표님 결정

## 10. 증적 규칙
- 시험ID별: 빌드 해시·커밋 ID(로컬 저장소), 환경(OS 빌드·.NET·브라우저), 실행 일시(KST), 결과, 로그/캡처 경로. 저장은 내부 PC 로컬 폴더 `qa\evidence\`만, 외부 업로드 금지.
