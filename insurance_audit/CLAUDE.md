# insurance_audit 작업 기억

보험금 심사에서 외부 손해사정법인으로 내보낸 조사 배당 데이터로 유착 혐의를
1차 발굴하는 도구. 이 폴더 작업 시 아래 내용을 전제로 하고, 이미 정해진 것을
다시 묻거나 다시 유도하지 않는다.

## 사용 환경 (제약이 설계를 지배함)

- **내부망 PC에서 단독 실행.** 외부 네트워크 없음. 패키지 설치가 막혀 있을 수 있음
- 데이터는 개인정보라 **반출 불가**. 실제 데이터를 볼 수 없으므로 합성 데이터로 검증함
- 원본은 SQL → 엑셀 → CSV 경로로 반출. 엑셀 파일 자체는 기술적 보호조치로 직접 읽기 불가
- **CSV 파일 읽기도 보안으로 막힘.** 엑셀에서 복사 → 붙여넣기가 사실상 유일한 입력 경로
- 규모: 지급 행 기준 10만 건대
- **의존성은 pandas / numpy / openpyxl 뿐.** scipy는 선택(없으면 정규근사).
  차트 라이브러리·그래프 패키지는 쓰지 않는다. 새 의존성을 들이려면 먼저 상의할 것
- HTML 보고서는 외부 자원을 부르지 않는 단일 파일이어야 함

## GUI (`gui.py`)

tkinter 기반 GUI. exe 실행 시 기본으로 뜬다. `--console`을 붙이면 이전 콘솔 모드.

- 엑셀 데이터 붙여넣기: `root.clipboard_get()` → `loader.parse_clipboard_text()` →
  탭 구분 텍스트를 머리글 그대로인 DataFrame으로 → 컬럼 매핑 확정 → `apply_mapping()`
- CSV 파일 열기: `loader.parse_table()` 경로 (보안이 허용하는 경우)
- 데이터 탭 "컬럼 매핑" 버튼으로 언제든 매핑을 다시 볼 수 있다
- 기준년 체크박스, 조직계층 드롭다운, 결과 폴더 선택
- 분석은 백그라운드 스레드에서 `main.run_pipeline()` 호출, stdout을 Text 위젯으로 전달
- CI에서는 GUI가 뜨지 않으므로 `--console` 플래그로 빌드 테스트를 돌림

## 컬럼 매핑 (`loader.py`)

머리글이 별칭표와 한 글자만 달라도 읽기가 실패하던 문제가 있었다. 점수식으로
느슨하게 맞춘다: 정확 일치 1.0 → 표기 흔들림 제거 후 일치 0.95 → 부분 포함
0.60~0.95 → 유사도 0.63~0.9. `MIN_MATCH_SCORE` 미만은 붙이지 않는다.

- **순서로 추측하지 않는다.** 컬럼 순서가 바뀌면 조용히 엉뚱한 컬럼으로 분석이
  돌아간다. 읽기 실패보다 나쁘다
- 뜻을 바꾸지 않는 흔들림만 걷어낸다(`성명`→`명`, `일자`→`일`, 끝의 `명` 제거).
  `코드`·`번호`·`id`는 컬럼을 구분하는 데 쓰이므로(법인 vs 법인코드) 건드리지 않는다
- `CONFIDENT_SCORE` 미만으로 붙은 것은 "확인"으로 표시해 사용자에게 보여준다.
  필수 컬럼이 비었거나 "확인" 항목이 있으면 `ColumnMapDialog`가 뜬다
- 사람이 직접 고른 항목은 확인을 마친 것으로 본다

## 데이터 구조에서 반드시 지킬 것

반출 표는 한 청구건이 **담보별·지급처별로 여러 행**에 나뉘어 있다(`하위클레임번호`,
`지급처순번` 존재). 행을 그대로 세면 조사 건수가 아니라 지급 건수가 잡힌다.
배당 편중을 행 단위로 집계하면 지급처가 많은 사고가 상위로 올라올 뿐 유착 신호는
묻힌다. 사용자가 이전에 직접 만든 프로그램에서 의미 있는 결과가 안 나온 원인으로
이것을 지목했다.

- `data["payments"]` — 지급 단위(원본 행). 지급처·예금주 분석, Benford에만 씀
- `data["cases"]` — 배당 단위(청구번호 × 손사법인). 나머지 지표 전부 여기서 계산

합의금은 피해자별 확정 금액이라 지급 행마다 반복된다. 행을 그대로 더하면 부풀려지므로
피해자 단위로 접은 뒤 합산한다(`prep._settlement_by_case`).

## 통계 설계 원칙

1. **기대값 대비 편차로 본다.** 단순 건수 1위는 업무량이 많다는 뜻일 뿐이다.
   기대치는 같은 점포 동료의 배당 분포에서 뽑되 **본인 건을 뺀다**(leave-one-out).
   본인 물량이 커서 기대치를 끌어올리면 편중이 정상으로 보인다.
   아무도 안 쓰는 업체는 기대율이 0이 되어 검정이 발산하므로 +0.5/+1.0 보정을 넣었다.
2. **비교 전에 층화한다.** 담보구분·사고원인·피해유형을 맞추지 않으면
   "그 법인은 원래 어려운 건만 받는다"는 반박에 결과가 무너진다.
3. **점수는 백분위가 아니라 유의도 척도로 편다**(`stats.signal_score`).
   백분위만 쓰면 차이가 없는 집단에서도 순위만으로 점수가 생긴다.
   실제로 "기대 20%인데 22%"가 92점을 받는 문제가 있었고 이 방식으로 고쳤다.
   각 지표 모듈이 `SCALE = (하한, 포화점)`을 선언하고 `add_score(..., scale=)`로 넘긴다.
4. **혐의도 = 0.6 × 가중합 + 0.4 × 최고지표.** 가중합만 쓰면 단일 지표 극단값이
   가중치 몫에 눌려 순위에서 밀린다. 실제로 Z=15.4인 법인이 10위권 밖으로 밀렸었다.
5. **등급은 혐의도와 최고지표 중 하나만 넘어도 부여**(`config.RISK_RULES`).
   주체 종류마다 적용 지표 수가 달라 가중합의 최대치가 서로 다르기 때문이다.

## 지표 구성

A 배당편중 · B 결과편향 · C 금액이상 · D 결재라인 · E 조사자편중 ·
F 지급처이상 · G 구상포기 · H 처리속도 · I 인물이동 · J 조직전환

가중치와 주체별 적용 지표는 `config.METRIC_WEIGHTS`, `config.ENTITY_METRICS`.
사용자가 D(결재라인)와 E(조사자편중)를 가장 무겁게 보자고 정했다.

핵심 두 가지:
- **I 인물이동** — 업체 선호가 조직이 아니라 사람을 따라다니는 경우.
  각 소속의 기준은 그 소속 동료에게서 따로 뽑고, 가장 약한 소속의 강도를 대표값으로 쓴다.
  검정은 **전체 인원으로 돌린다.** 이동자만 남기고 돌리면 기대율을 낼 동료가 사라져
  기준선이 본인 실적으로 대체되는 버그가 있었다.
- **J 조직전환** — 담당자는 그대로인데 결재자만 바뀌면서 지점 위임처가 통째로 옮겨간 경우.
  사용자가 실제로 받은 제보("대전물보험에서 팀장 교체 후 B업체 → C업체")가 이 형태다.

## 검증 방식

실제 데이터를 볼 수 없으므로 `make_sample.py`가 유착 패턴 10종을 심은 합성 데이터를
만든다. `SEEDED` 딕셔너리가 정답지다. 지표를 고치면 **반드시** 합성 데이터로 돌려
심은 대상이 상위에 오는지 확인한다.

현재 검증 상태(45,000건 기준): 10종 모두 탐지. 담당자 상위 4명이 전부 심은 대상이고
5위(19.2)와 간격이 뚜렷함. 법인 상위 6곳도 전부 심은 대상.

## 도해

`charts.py`. 차트 라이브러리 없이 SVG를 직접 그린다.
색 슬롯은 색약 조건에서 인접 색이 구분되는지 검증한 고정 순서이며 **섞거나 늘리지 않는다**.
슬롯(6개)을 넘기면 꼬리를 "기타"로 접는다. 값은 항상 숫자로도 적어 색만으로 읽게 하지 않는다.
밝은/어두운 모드에서 셀 글자색을 뒤집는다(`cell-ink-strong` / `cell-ink-weak`).
